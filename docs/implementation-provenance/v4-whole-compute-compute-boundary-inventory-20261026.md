# MECO v4 whole-compute boundary inventory

**Inventory only.** This is a static source audit for item 2 of the Pass 1 plan `docs/plans/v4-whole-compute-gpu-residency-20261026.md`. It does not authorize or claim a code port, test, profile, simulator run, calibration, device check, or campaign change.

**Source base:** `53f3d9c9a49a7e12bf65b5e1fa2797f4464e63be` (the requested isolated-worktree base).

**Method and limits:** Python/native source and existing protocol documentation were read without importing the application or inspecting runtime state. “GPU” below means tensors explicitly constructed on or retained on `env.device`/the configured indexed device in source; no runtime placement was observed. The audit found open host numerical paths and host decisions, so the present source does not satisfy the user's zero-CPU-algorithm requirement. A producer-to-consumer trail is provided for each requested compute class; lower-level physics extensions and every transitive utility call still need dedicated implementation-stage call-site review.

## V4 estimand and non-regression constraint

The existing v4 qualification estimand is retained unchanged. In `meco_qualification.py::_cluster_bootstrap_ci`, each draw resamples the complete frozen layout/defender-family groups, then paired episode rows within each sampled group; `consume_validation_round` applies it to candidate-reference useful-throughput differences and candidate/D0 safety differences. Exact strata and seeds, sample coverage, gate thresholds, consecutive-pass rules, checkpoint/reference/source bindings, and protocol identity remain the qualification contract. The separate paired-calibration seed-cluster bootstrap and D0/repeated-reference summary routines are different estimands and are separately identified above.

## Unclassified items and next source-audit boundary

- This is a map of the principal live entry paths and obvious tensor-to-host/scalar sites, not an exhaustive audit of every imported simulator physics helper, generated native kernel, legacy comparator, replay hook, or all five track-specific model adapters. Those transitive edges need a dedicated callsite-by-callsite pass before source freeze.
- `meco_track_training.py` interleaves telemetry/replay materialization and execution control. Each individual conversion needs a later dataflow audit to prove that it occurs only after a numerical decision is final; its presence in report-building code alone is not proof.
- Device index validation, native-extension identity, and tensor constructors are source-level guards only. Expected WX9100 identity, exclusive leases, actual kernel placement, no-hidden-sync behavior, and profiler evidence require the later approved readiness/profile stage.
- Some legacy CPU/reference APIs are intentionally retained for offline fixtures. Their reachability from live training/evaluation must be verified at callsites when implementing GPU-only boundaries; do not use the reference path as runtime fallback.

No changes to the v4 protocol, score estimand, bootstrap semantics, training artifacts, dashboard, campaign, or service configuration are part of this tranche.
