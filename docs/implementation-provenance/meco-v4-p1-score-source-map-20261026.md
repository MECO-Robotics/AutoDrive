## Source facts versus unresolved contract

The accepted ABI fixes the V4 row field names, types, byte widths/order, capacity and registered codes. At this base, the following required event semantics are not source-defined. This P1.1 map therefore **does not authorize P1.3 producer or consumer edits**:

1. **Physical incarnation:** slots are reused after score/respawn, but there is no `piece_generation` state or initialization/increment/reset/exhaustion lifecycle. Do not assume generation zero or invent an increment rule.
2. **Event sequence:** no episode-local `episode_event_sequence:uint16` counter exists in the source. The accepted Gamepiece/score owner response (commit `3738ad58fc883c5853b32c508e89ac657864bca4`, review `8e58451551c82c4713688e3fd228a9b410125e2155157f437e75679b2e3601ac`) defines sequence as episode-local and says it restarts only under a new `episode_generation`. That reset contract is fixed. The pinned source still does not define deterministic ordering/allocation for multiple same-tick awards across the vectorized and robot-loop paths. Do not choose an order from branch, robot loop, or tensor layout without a reviewed owner addendum.
3. **Tick and elapsed-time sample:** `steps` and `match_elapsed` advance before `_update_fuel`; the ABI does not specify zero/one-based `tick` or exactly which `match_elapsed` sample belongs to the event. Line order alone does not settle the intended contract.
4. **Canonical ledger consumer:** the P0a-defined whole-alliance event-ID aggregation module is absent at the approved implementation base. Existing reward, curriculum metric, metric ledger and evaluation aggregates are not substitutes.

The source map confirms the score-producing mutation sites and their current consumers, but cannot safely resolve these four items using only the pinned source and accepted contracts. P1.1 is therefore **complete as an evidence map and blocked as semantic closure**. Stop before event-producing code. The smallest next action is a separately reviewed gamepiece/score-owner addendum defining physical generation lifecycle, deterministic within-episode event ordering/allocation, and tick/elapsed-time sampling; resolve the absent ledger module through a reviewed base/module decision. The episode-local sequence reset under a new episode generation is already fixed by the accepted owner response and must be preserved. Any required ABI field meaning/width/code change returns to ABI reconciliation and requires a new P0a decision and profile hash.

P1.2 may implement only the fixed-byte schema/API specified by the accepted P1 plan; it must not make unresolved event semantics normative. P1.3 and P1.4 remain blocked until the source-map questions close under reviewed authority. P5 remains sole owner of trainer integration.
