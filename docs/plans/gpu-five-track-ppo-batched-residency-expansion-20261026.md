## Why the previous scope stopped

The previous plan correctly identified _gae and _ppo_update as shared numeric targets but authorized only meco_track_training.py and a test module. Pass 2 audited the actual interfaces and stopped before edits because:

- _ppo_update receives a heterogeneous Python list of dictionaries; _policy_inputs_for_row branches over Python row fields and objects.
- score_candidates explicitly rejects batches with B != 1. The existing C1/C2 model modules can score candidate axes but their adapter and metadata checks only accept a single decision.
- A1/A2/A3 rows carry variable-size PlanAActionSupport, graph tensors, route/path metadata, and planner objects. gather_pose_behavior_logits and _plan_a_logits consume a single support/graph at a time.
- A device-generated permutation cannot index Python dictionaries without converting each selected index to a host value. order.tolist() is the current explicit synchronization.
- Replay identity is currently assembled partly from Python metadata and host hashes. Plan A hashes device support but copies digest bytes to host; C replay fingerprints copy feature, route, risk, model and observation values to CPU for hashes and diagnostics.

These are source-interface facts, not performance estimates. A per-row loop with a device index does not solve dispatch while the row remains a Python object. This expansion therefore includes a fixed-shape device batch, a batched scorer seam for every architecture, device replay validation, and optimizer/RNG provenance. No host-indexed row fallback is allowed.

## Objective and boundary

Implement one versioned, fixed-capacity PPO tensor contract consumed by A1, A2, A3, C1 and C2. Rollout numeric state, model inputs and outputs, support/candidate identity, replay verdicts, GAE, stochastic policy distributions, sample order, PPO loss, gradients, Adam state, update counts, RNG state, and numeric diagnostics remain on the explicitly assigned WX9100. Python may enumerate static module fields and fixed slot positions; it may not read a tensor-derived row index, validity bit, count, verdict, or statistic to select or skip numeric work.

This tranche covers the shared on-policy rollout-to-update seam and the batch adapter it needs. It does not claim to close the whole-compute GPU plan: supervised Phase 2 fitting, simulator physics/observation, general evaluation and aggregation, artifacts outside the PPO checkpoint/RNG boundary, qualification, and promotion remain separate work.

## Versioned batch contract

Pass 2 must publish the exact field schema and capacities before production edits. The contract has fixed rollout capacity R=rollout_steps, fixed candidate capacity K taken from the integrated device candidate contract, and fixed A support/graph/edge capacities derived from the attested legal-graph schema. The A support bound must be justified from the canonical support construction (including descriptor multiplicity); it may not be guessed from observed rows. If any field has no defensible finite cap, stop and revise the contract. Variable actual counts are represented only by device validity masks and padded slots.

The common header contains contract version, track/model schema ID, device/backend identity, rollout generation, and tensor layout IDs. Numeric fields include raster/global/hidden inputs; selected action index and sampled old log probability; reward, value, terminal/truncation and execution-failure status; actor/critic validity; candidate/support IDs and masks; route/risk/path costs; per-row replay digest bytes; and slot validity. A tensors include padded graph tensors, node/behavior/descriptor identity, root/path metadata and support digest bytes. C tensors include the frozen candidate feature/missingness tensor, stable integer candidate order, valid mask, route/risk values and candidate digest bytes. Host may validate static shape, dtype, device and schema metadata; dynamic values, bounds, mask relationships and replay results are checked by device predicates before the first optimizer mutation.

The host may write the predetermined slot number because it is a static rollout counter. The host may not select the destination slot from a device value, inspect actual support/candidate count, compact Python rows, or build numeric payloads from Python lists. Padding is produced and masked on device. A row whose execution failed remains critic-only exactly as today; an inactive padded slot has no GAE, loss, optimizer, RNG-order, or diagnostic effect.

## Batched policy and replay contract

1. **A models:** execute each existing A1/A2/A3 forward on the padded observation/graph batch. Gather U + behavior logits, learned P/path cost, route/risk cost and support mask using batched tensor indices. Padding is always invalid. The output is masked categorical logits over exactly the same ordered legal node/behavior/descriptor support that generated the sampled action.
2. **C models:** execute C1/C2 forwards on the padded candidate axis and use the same frozen candidate feature normalization, missingness, mask, route/risk terms, hysteresis inputs and candidate order. Padding cannot become selectable. The selected action's index and log probability remain paired with the exact immutable candidate row.
3. **Distribution invariants:** preserve current categorical sampling temperature (if configured), masking, entropy calculation, action/log-probability pairing, candidate/support order, fallback, recurrent hidden-state semantics, and each track's actor/critic parameter coverage. No batch-axis normalization or pooled context may alter outputs relative to the existing one-row reference. Batched score parity is checked on active rows before optimizer changes.
4. **Pre-mutation replay:** recompute policy logits and selected log probabilities for every active row as a device tensor batch. Recompute canonical A support/graph and C candidate/route/risk fingerprints from exact padded tensors and static schema IDs, compare device digest bytes and log-probabilities using the existing declared tolerance, and reduce all checks into a typed device status. Any failure gates the entire update to a no-op before parameter or optimizer state mutation. Host-readable string hashes are report-only after the attempted update has reached a terminal status.
5. **Static identity:** candidate/support membership and ordering are inputs owned by upstream reviewed plans. Stable integer IDs and versioned order digests are bound into tensors. A Python CandidateTable, dataclass or digest string cannot reconstruct, accept, reject, reorder or mask a training row.

## Exact optimizer, order and RNG semantics

The current contract is shuffled single-transition Adam: for each epoch, visit each real rollout transition exactly once in a device-generated permutation and perform one Adam update for that transition; execution-failure rows still perform the existing critic-only update. Preserve clipping ratio, value coefficient, entropy coefficient, advantage normalization population/epsilon, terminal versus truncation bootstrap, GAE lambda/gamma, gradient clipping norm, learning-rate schedule and update cadence.

To remove device-index-to-Python dispatch, iterate only over the fixed host-known slot positions 0..R-1. At each position, gather the permuted row with a one-element device tensor index and run the same one-row-equivalent loss. Use a device-masked Adam state transition for invalid padding slots so parameters, moments, and step counters remain bitwise unchanged; do not call ordinary optimizer.step() for every padded position. This update mechanism must also gate the complete optimizer state on replay/schema failure. If PyTorch/HIP autograd or the optimizer cannot maintain exact sequential Adam semantics with no device-to-host synchronization, stop; do not batch/average gradients, update once per minibatch, use tensor-derived Python branches, or accept optimizer-step drift.

Use explicit HIP-device generators for action sampling and per-epoch permutations, with independent versioned streams or a fully specified shared stream. Device RNG state and counter progression must be saved and resumed exactly. A host-created seed may initialize the device generator; host CPU RNG and Python row order cannot decide action sampling, permutations, model initialization after initial seed transfer, or continuation. The checkpoint schema must identify the new batch, optimizer and RNG state versions; incompatible legacy checkpoint state fails closed instead of silently restarting a stream or adapting CPU state.

The optimizer implementation may use static Python iteration over model parameter names, because parameter names/order are schema metadata. Its values, moments, step tensors, bias correction, clipping, and active/no-op predicate must remain on-device. If the implementation requires a custom operator or build target outside the exact table above, stop and revise Pass 1.

## Non-numeric host boundary

Allowed host work is static model/track dispatch, fixed slot enumeration, filesystem/device scheduling, final compact action dispatch, opaque checkpoint/replay byte I/O, and typed status/error routing. Passive diagnostics may be copied only after PPO update completion and may not gate training continuation, row inclusion, loss, optimizer state, RNG state, qualification, or the typed device verdict. The host may route a typed failure status to stop orchestration after the attempted update is a device-gated no-op; it may not derive or reinterpret that status from numeric values. No .item(), .tolist(), .cpu() numeric conversion, NumPy conversion, Python bool(tensor), host reduction, row dictionary selection, or CPU hash of dynamic PPO inputs may control training. Device-side finite checks and verdicts are required.

The source evaluation plan's PPO requirement is satisfied only if sampled categorical distributions and matching sampled log probabilities remain valid for all five tracks. A completed tensor update, finite loss, or passing tests are not game-behavior, evaluation, or curriculum evidence.

## Acceptance evidence for implementation

- Each of A1/A2/A3/C1/C2 uses the same fixed-capacity device batch and batched model seam; no qualifying path accepts Python row dictionaries after collection or falls back to single-row host-index dispatch.
- For mixed active/inactive rows and variable A/C support sizes, batched model outputs, masked categorical probabilities, selected-action log probabilities, hidden states, value inputs, GAE, clipped losses, entropy, gradient norms, and sequential Adam state equal the frozen per-row reference within explicitly predeclared numeric tolerances.
- Device-generated permutation indices are consumed only by tensor gathers. No row index/count/eligibility/status becomes a Python scalar. The optimizer performs exactly one sequential Adam state transition per active real row and preserves optimizer parameters/moments/step counts on padded rows.
- Adversarial tests mutate each A support/graph component, each C identity/feature/missingness/mask/route/risk field, selected action/logprob, schema version, device, and padding metadata. Device validation rejects the complete update before any model or optimizer mutation.
- Fixed-seed run and checkpoint/resume produce identical next action/permutation, rollout schema, optimizer state and update result for all tracks. Incompatible checkpoint versions fail closed.
- Device traces show all dynamic PPO data, fingerprints, comparisons, RNG progression, GAE, losses, gradients, Adam states and update decisions remain on the attested WX9100. Typed failure status and passive metrics do not control individual rows or partial updates on host.
- Exact Pass 3 head, tests, device/lease provenance and any later simulator/dashboard evidence are reported separately. No result is represented as five-track training completion, stage-1 pass, held-out success or whole-compute GPU-only closure without the corresponding independent requirements.

## Stop and re-review conditions

Stop before source edits if fixed caps cannot cover every legal Plan A support row and C candidate row; if a required field can only be reconstructed from Python objects; if candidate IDs/order are not represented in the approved device contract; or if graph/planner objects do not expose fixed-shape tensor state. Stop if batched model forward changes any active row's distribution, recurrent state, support order, or loss semantics; if exact sequential Adam and zero-effect padding cannot be implemented without tensor-to-host synchronization; if the native/backend stack requires a new target not listed above; if replay status or failure handling branches on host numeric values; or if checkpoint/resume cannot reproduce the exact device RNG and optimizer progression. Any such case requires a new exact-file Pass 1 plan. No CPU numeric fallback, weakened replay validation, changed optimizer cadence, or reduced track coverage is allowed.

This is a proposal only. It does not assert that batching, masked Adam, checkpointing, parity, GPU residency, simulator behavior, dashboard currentness, training, or qualification currently works.
