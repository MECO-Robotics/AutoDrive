## Goal and semantic boundary

For each scored simulator episode, retain an immutable event ledger whose outcome can be recomputed from its ordered events and frozen simulator scoring contract, and can be checked independently against a fresh replay. Report the simulator's modeled score explicitly as a simulated outcome. Do not call it official FRC match points, ranking points, or policy-attributed causal contribution. Keep the production FRC scorer (`official_match_points`) separate; current simulator events do not contain the sensor, referee, tower adjudication, match roster, and disqualification evidence required by that scorer.

The current six-robot simulator increments `fuel_score_count` by accepted score actions, and the step reward uses the current tick's `fuel_scored_event` as a zero-sum signal. Those values are useful cross-checks and training signals, but are not themselves the new outcome record. The versioned scorer must derive each alliance's simulated score by summing explicit, immutable score-award events with a rule-defined value, then compare the derived result with the simulator counters. Preserve scored-FUEL count and useful throughput under their existing names and meanings. Never alias either field to `match_points`.

The model's current score semantics award one simulated score unit when a held FUEL piece passes the simulator's existing score eligibility gate: valid score intent, active HUB, alliance zone, robot readiness, match cadence, and active world. This is only a candidate estimand: **no outcome-bearing data collection may begin until a human-authored, immutable estimand-review artifact approves this exact limited scope**. The artifact must identify the intended primary estimand and use, define the score unit and included mechanics, enumerate excluded mechanics, and bind the source, scoring-rule ID/version and digest. If the approved scope includes any currently excluded or unmodeled outcome (such as tower/end-game awards, foul/penalty points, disqualification effects, or advancement/ranking points), the current ledger must remain incomplete and collection must stay blocked until a revised scorer/event schema covers that scope and a replacement estimand artifact approves the new exact contract. The implementation must pin the approved semantics and source/runtime identity. If source inspection during implementation finds another score-bearing event or terminal adjustment within the evaluated approved scope, include it in the rule contract or keep the outcome incomplete; do not infer it away.

## Implementation contract

Implement one new pure, versioned simulator score-accounting module and integrate it at the simulator's accepted score-event mutation and MECO episode/replay boundaries. Proposed public identifiers:

- Schema: `meco-simulated-score-ledger-v1`.
- Scoring contract: `meco_simulated_fuel_score_v1`.
- Replay event stream: `meco-score-events-v1`.
- Outcome field: `simulated_match_score` with `{schema, rules_id, rules_sha256, red, blue, complete}`. It is explicitly a modeled simulator outcome; `official_match_points` remains null/unavailable unless separately supported by the existing evidence contract.

Each normalized event must bind at least: unique deterministic `event_id`; zero-based physics `tick`; finite `match_elapsed_s`; simulator world slot; alliance/team and robot slot; `piece_slot` and `piece_generation`; event type `fuel_score_awarded`; integer `score_units` fixed by the pinned rules contract; and source event site/semantics. The event order is `(tick, event_id)`. A pool slot can be reused after score respawn, so slot/index alone is not a piece identity. Generation is scoped to `(episode_id, world_slot, piece_slot)`, starts at generation zero for each initialized MECO episode incarnation, and advances exactly once when an accepted score consumes that incarnation and respawns the slot. Bind the award to the pre-increment generation. MECO's score-and-respawn mutation is in `gamepiece_actions.update_fuel_actions()`; initialize/reset generation state alongside `_initialize_fuel()` in `_tensor_3v3_gamepieces.py`. Do not include the separate `TensorDefenseEnv` fused-gamepiece kernels in this ledger's source or validation scope. Reject duplicate IDs, unknown slots/alliances, non-finite or out-of-range clocks, negative units, duplicate awards for an identical `(episode_id, world_slot, piece_slot, piece_generation)`, reordered rows, and event rows inconsistent with the simulator's accepted-score source. Accept a later legitimate award from a reused slot only when its generation has advanced. Preserve enough runtime/source identity to reject cross-source replay.

The episode ledger must include exact match context (seed, scenario, team/robot slot map, simulator source identity, effective scoring configuration identity, and the digest of the matching approved estimand artifact), rules identifier and content digest, canonical event rows and per-event digests, aggregate event digest, red/blue derived totals, independent terminal/censoring state, and its own canonical digest. It must distinguish `complete`, `incomplete`, and `invalid`; incomplete source coverage must yield no complete outcome, never zero. Collection and intake must reject missing, unapproved, stale, or mismatched estimand approval. If the approved estimand includes an outcome class absent from the event source/schema, the episode is `incomplete` and collection remains blocked until the scorer/schema is revised and a replacement artifact approves that exact contract. No per-robot causal contribution is reported from whole-team score events. A robot-attributed subtotal may be emitted only as a descriptive event attribution with no causal language.

The prerequisite approval artifact should use a strict versioned schema such as `meco-simulated-score-estimand-review-v1`; it is authored and approved by a human outside the data-collection job. It binds the source-plan and Phase 0 plan digests, simulator/source identity, simulator-score schema and rules digest, primary outcome name/formula/unit, included and explicitly excluded scoring/terminal effects, interpretation limits, intended comparison use, approver identity and approval time. It is immutable once outcome data are collected. A scope or scoring-contract change invalidates the artifact for subsequent collection.

Replay integration must place the exact ordered event rows (or a lossless, digest-bound event stream) in the replay artifact at their original physics ticks. A pure reconstruction function consumes only replay identity/context, the pinned score rules and replay event stream; it recomputes all team totals and the ledger digest. It must not read the evaluation row's totals, `fuel_score_count`, `fuel_scored_event` aggregates, throughput, or training rewards as inputs. The replay validator then compares reconstructed output with the evaluation row and the terminal simulator counters, failing closed on any disagreement.

The simulator's currently modeled outcome is intentionally limited to its actual FUEL score-award mechanics. `tower_award`, foul/penalty, disqualification, ranking points, end-game bonuses, and official advancement points are not implied or silently synthesized by this simulated contract. If a future simulator adds such mechanics, a new versioned rule/event contract is required or the existing episode must be marked incomplete.

## Acceptance tests and mutation matrix

Pure-contract tests must verify deterministic aggregation and digests for hand-constructed event sequences; score value derives from validated event rows/rules; same input produces byte-stable canonical output; missing required context or coverage is incomplete; and unrecognized scoring rules fail closed. Integration tests must execute the real simulator score path and compare emitted events, terminal team counters and observed production reward while toggling capture.

Required mutations must be rejected:

1. Delete one event while leaving replay counters unchanged.
2. Duplicate an event ID or duplicate a piece award for one incarnation; reorder same-tick or cross-tick events. In MECO's actual scorer, score one incarnation, let its slot respawn, then score that slot again: accept the two distinct generations and reject a duplicate for either identical `(episode, world, slot, generation)` tuple. Cover both vectorized-six-robot and robot-loop scorer paths, plus episode/reset generations.
3. Change tick, clock, alliance, robot/team attribution, piece identity, score units, scenario seed, or source/rules digest.
4. Alter scorer rules/version and replay only a prefix under the prior digest.
5. Change replay events but leave its score ledger/evaluation record unchanged; change the evaluation summary alone; or make summary and replay disagree while recomputing only the outer file hash.
6. Substitute `fuel_score_count`, `fuel_scored_event` aggregate, `useful_throughput`, or reward total for event-derived score; assert rejection and assert these values remain separately named in valid output.
7. Emit an event from an inactive world or outside a successful simulator score mutation; assert rejection or incomplete capture.
8. Attempt to populate `official_match_points` or claim qualification eligibility from this simulator-only ledger; assert rejection.
9. Compare event capture on/off for identical seeded inputs and prove score counters and rewards are unchanged. No test may change raw scoring, reward, cadence, random-number consumption, or dynamics.
10. Omit or mutate the estimand approval, use an approval bound to a different scorer digest, or attempt collection before approval; assert collection is blocked. Approve a scope containing excluded awards/penalties absent from the schema; assert the ledger is incomplete and collection remains blocked until implementation and a replacement approval cover the exact scope.

Existing regression coverage to inspect and extend includes `tests/test_rebuilt_match_scoring.py`, `tests/test_meco_evaluation_dashboard_replay.py`, and score-action coverage in `tests/test_tensor_3v3_physical_constraints.py`. Passing pure schema tests alone does not establish simulator behavior.
