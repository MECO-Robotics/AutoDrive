## Objective and source audit

Keep each selected policy action and its associated identity, goal, route evidence, log probability, recurrent state, macro outcome, remasking, terminal state, and reward on the explicitly selected HIP device from policy selection through simulator consumption, PPO transition storage, replay validation, and artifact serialization. This applies uniformly to A1, A2, A3, C1, and C2. No CPU action/row/candidate-ID/numeric transfer, host-selected lookup, scalar-dependent host control, or CPU numerical fallback is allowed in a qualifying path.

## Pass 1 amendment: canonical command production and status propagation

This amendment proposes the missing source-level command/status handoff. It is one coordinated producer/consumer contract for A1/A2/A3 and C1/C2; it does not authorize implementation. The shared ABI field-table amendment is pinned as `docs/plans/gpu-shared-command-ppo-transition-abi-20261026.md`, commit `1c7e9ef02030fa519325c44aa12d4b07e5d171cc`, SHA-256 `65a4d936deb792b26b61b7569fec992dc8d35ec9da11c02845fcf342fa4b7f30`; it has independent Pass 1 and Pass 3 acceptance as a planning artifact. Its unresolved capacities, lifecycle, status-code, RNG, digest, and record-envelope decisions still block source implementation. No PPO-owned field may be emitted or consumed until those decisions are resolved in an accepted schema revision and the PPO owner publishes a matching accepted amendment.

### Single command producer and source mapping

`FiveTrackDeviceActionCommandV1` from the pinned shared ABI is the only command type. There must be no parallel Plan A command consumed by the simulator, compact C command, action-index dispatch record, or Python-selected row. The producer first gathers the model-local choice and associated evidence by device tensor indexing, then writes every common command field into a fixed `[N,S,...]` device envelope (and, where the accepted PPO profile requires it, gathers through the device rollout row map into `[R,...]`). It may not create a Python int, string, object, or dictionary for any selected row.

| Track producer input | Required device binding into the one common command | Owner constraint |
|---|---|---|
| A1/A2/A3 Plan A support | `policy_local_index` aliases Plan A `local_support_row`; `source_global_row` aliases `global_support_row`; preserve `legal_node_id`, `behavior_id`, `descriptor_id`, `action_id`, `goal_xy`, `goal_heading`, `target_identity`, `route_override`, `fallback`, and selected U/P. | Plan A support-selection owner supplies tensor outputs and status. The command producer must not reconstruct support identity from a Python `PlanAActionSupport` object or action code. |
| C1/C2 ordinary selection | Bind local slot `j` separately from `ordinary_row_map[j]`; gather identity/action/goal/target/route and descriptor from that exact source-global row. Preserve K=8/16/32 and non-prefix selection. | Plan C model-view owner supplies the accepted K/K+1 map. No local/global alias, compacting, host table lookup or candidate ID string. |
| C1/C2 continuation | Bind local slot K separately from `continuation_row_map[0]`, which equals the exact source-global `continue_index`; preserve its existing identity/action/goal/target/route. | Do not add `policy_stop` or use local K as the global row. |
| All five tracks | Fill `schema_version`, `track_code`, `decision_valid`, stable numeric identities, goal, route fields, validity/fallback, and Plan A-only payload with neutral values for C under the ABI’s device tag. | All fields are device tensors with canonical ABI dtypes. Static dispatch may select the compile-time track path; it cannot inspect a dynamic track/action tensor on the host. |

Every producer result is accompanied by device-side validity inputs: selection/support validity, source-global range and mapping consistency, candidate identity binding, finite goal/cost/utility values, route query/result association and any Plan A HIP support status. `decision_valid` is produced as a device boolean from the conjunction of the applicable checks and the accepted action/route requirements. Invalid or unsupported state yields a typed invalid command and a no-op status; it cannot be repaired by host fallback. The exact route-status numeric map, route-required action classes, neutral command values, and any sentinel registry must be fixed by the shared ABI owner before this producer is implemented; this amendment does not guess those values.

### Status lifecycle and PPO handoff

The command's `decision_valid` means the device has a valid, supported policy decision and all required command-side bindings passed. `route_status` remains the typed status field in the shared ABI, but the conversion from route result status (`int64` query result) to command `uint8`, the valid status set, and behavior for actions that require no route are unresolved. The ABI owner must specify these mappings and the simulator owner must confirm the pre-mutation gate consumes them consistently. A command-invalid result must not be represented by a success route status or by a host exception.

The simulator consumer returns device tensors for native acceptance/execution status and per-tick macro outcomes without mutating state on failed preflight. The training macro carries the original command plus these returned values to PPO. Once the complete V3 schema is accepted and source-ready, PPO writes `decision_valid`, command `route_status`, device/native execution status, selected and executed action, remask, target-loss/preemption/fallback, actor/critic eligibility, lifecycle masks, reward and RNG/provenance fields only into the canonical `FiveTrackPpoTransitionV3` row. It must preserve the command-to-row ownership map and validate that one active command owns one row. The shared field-table draft does not yet pin every such field’s type, shape, capacity or status code; thus the V3 row writer/handoff is explicitly blocked pending the schema-owner decisions and a new exact ABI artifact hash. No PPO partial row is authorized by this amendment.

The order is: (1) accept the shared ABI field-table artifact and resolve all schema blockers in a reviewed revision; (2) Plan A, Plan C, action/macro, simulator/gamepiece and PPO owners reconcile the common command/status interface and path allowlists; (3) independently Pass 1 review each owner amendment; (4) implement only from a single pinned source base in isolated worktrees; (5) independently Pass 3 review each exact implementation head and the integrated source head before any merge/integration; (6) after manual stop of the continuous campaign and independent verification that both WX9100 leases are released, run only the accepted device tests and simulator/dashboard gates. Diagnostic evaluation remains unbound and cannot count as a Stage 1 pass. Until the live campaign is manually stopped and leases released, all device tests, simulator evaluations, dashboard replay operations, checkpoint operations and training/campaign transitions remain closed.

## Canonical row and identity rules

1. **One transition ABI:** the canonical record is `FiveTrackPpoTransitionV3` within `FiveTrackPpoBatchV3`, as specified by the accepted shared ABI field-table artifact `docs/plans/gpu-shared-command-ppo-transition-abi-20261026.md` (commit `1c7e9ef02030fa519325c44aa12d4b07e5d171cc`, SHA-256 `65a4d936deb792b26b61b7569fec992dc8d35ec9da11c02845fcf342fa4b7f30`). That planning artifact has Pass 1 and Pass 3 acceptance, but unresolved schema fields remain blocked until a later accepted revision pins them; it does not authorize the PPO row writer. Action/macro code contributes tensors to the finalized row; it must not define a route-only record, `meco-route-evidence-device-v2` sidecar, second serializer, shadow trace, or parallel digest path. The existing evaluation replay bundle carries the same row schema. V1 data remains readable only as historical input and is never relabeled as current v3 evidence.
2. **Policy-local versus source-global indices:** record the policy-local selected index and mapped source-global row as distinct fields. The policy-local index addresses the model’s ordered utility/mask vector. The source-global index addresses the canonical full candidate table and its descriptor/action/goal/target/route columns. Never substitute one coordinate for the other or renumber a selected row while serializing.
3. **Plan C ordinary and continuation identity:** for K in {8,16,32}, ordinary local slot `j` maps through `ordinary_row_map[j]` to source-global `selected_policy[j]`, including non-prefix rows at K=16/32. Local continuation slot K maps through `continuation_row_map[0]` to the exact source-global `continue_index` defined by accepted normative amendment `8556c82b7` (artifact SHA-256 `782279be4857e849f9f90d2f6e938b22b244d34b5567f562847e61b88ebf4fb9`). Its accepted review-status refresh is `4cdc30f92` (same document path, artifact SHA-256 `6d9c0e6320acd503c8595fa619e8beeba24af88f36e49337d7325331a899ff0b`). Preserve the existing continuation identity (`continue:inactive` or the active commitment’s existing `continue:<candidate ID>`), descriptor, action, target/goal and route binding. Do not create a new stop action/token; do not treat local K or a compact-table display slot as a source-global row. The same mapped global row and descriptor must bind to selected log probability, macro command and TransitionV3.
4. **Plan A identity:** preserve the exact sampled support row `(node, behavior, descriptor)`, selected support index, action/goal/target and selected log probability. These Plan A values bind to `FiveTrackDeviceActionCommandV1` and its canonical V3 fields under the shared ABI; the accepted `DevicePlanAActionCommandV1` fields remain semantically preserved as specified aliases. No Plan A support value is reconstructed from Python objects or inferred from action code.
5. **Status and learning semantics:** the canonical transition row records per-tick executed action/remask/target-loss/native-preemption/fallback status, terminal/truncation, reward, actor eligibility, critic validity, recurrent reset/hidden state and RNG progression using the PPO owner’s fixed tensor schema. A remasked or failed transition retains existing critic-only semantics. Do not change macro cadence, reward, tie behavior, action/goal support, candidate recall, target revalidation, native safety, commitment expiry, seed progression, probability distribution, or PPO optimizer semantics.
6. **Opaque output boundary:** dynamic record bytes and any integrity/status values are created and validated on-device. Host code can allocate the predeclared batch slot/path and write/read completed bytes unchanged. It must not inspect action/row/ID/route/terminal values; format a dynamic string; compute a dynamic hash; reconstruct JSON; aggregate metrics; or let an output parse determine continuation, row eligibility, evaluation, campaign sealing, readiness or qualification. If the approved replay/display contract cannot preserve opaque I/O, stop; do not introduce a host decode exception here.
