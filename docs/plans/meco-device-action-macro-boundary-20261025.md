## Finding and why this is a narrow amendment

The code audit found an uncovered training-to-simulator boundary. The current Plan A decision plan permits a compact chosen-action payload to cross to Python, and the PPO batch expansion retains a compact dispatch boundary. That clause is incompatible with the literal persisted requirement and leaves live action and macro decisions host-controlled. This amendment removes that exception for the training path only. It does not replace or repeat the existing Plan A, Plan C, candidate/route, PPO, observation, simulator-physics, or whole-compute GPU plans.

The exact existing plan documents at this planning base are `docs/plans/gpu-resident-plan-a-decision-slice-20261025.md` (SHA-256 `21b5610319116ee80e95cdcc668c4caa3491dd8b2a204e7fdf71bd8366f87235`) and `docs/plans/gpu-five-track-ppo-batched-residency-expansion-20261026.md` (SHA-256 `61613da9f120d3ee22b53b9a09de529ea6981e3639bd43a1fcea966654a85b0b`). Amend their chosen-action clauses for the strict campaign before implementation; do not broaden this tranche into their support, candidate, route, replay, or optimizer scopes.

Telemetry reporting A3/C1 workers on `cuda:0`/`cuda:1`, with both devices busy and high worker host CPU, does not by itself establish a CPU numerical violation or identify its cost. The source evidence below does establish host synchronization and host-dependent control in the training path. This plan makes no performance attribution from utilization.

## Device-resident behavior contract

1. Selection and goal binding remain device tensors from the policy output through `env.step`; no `.item()`, `.tolist()`, `.cpu()`, `.numpy()`, Python `bool(tensor)`, or device-value-to-host tuple conversion may occur before native simulation has consumed the command.
2. Per-tick action remasking, target validity/loss, goal distance/heading, `done`, `truncated`, safety counters and macro-active state remain device values. Host iteration may use only the configured constant `action_ticks`; it may not break, skip, classify a row, or advance the training/episode schedule based on a dynamic tensor value.
3. A device failure or invalid selected goal must become a device-gated no-op/failure state before any unsafe simulator mutation. If the current backend cannot provide this guarantee without host synchronization, implementation stops; it must not weaken validity checks or call `.item()` as an escape hatch.
4. A/C action identity and Plan A goal descriptor / Plan C candidate identity stay paired with the exact selected log probability and replay record. Any final artifact write is downstream of the executed decision and cannot determine the executed action, actor/critic row mask, macro continuation or episode reset. Dynamic numeric reporting is outside this tranche and must follow the separately approved artifact boundary; it cannot be passed off as orchestration to satisfy the GPU-only requirement.
5. No policy, curriculum, simulator behavior, qualification estimand, source identity, or checkpoint compatibility may be inferred from the static plan. Source identity and any changed implementation/protocol must be regenerated before a future campaign.
