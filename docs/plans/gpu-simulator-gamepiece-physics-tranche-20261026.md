# Pass 1 plan: GPU-resident simulator gamepiece physics and event control

**Status:** planning only; static source/architecture audit. No code, tests, simulator, GPU, device lease, dashboard, or campaign changes are authorized here.  
**Planning base:** `main` at `9497615c9cbd355b8b065e9ccd9b7ead87ad00be`.  
**Execution constraint:** the live diagnostic r4 campaign remains untouched and uninterrupted. Defer fixtures, GPU checks, profiling, and simulator evaluation until r4 is manually stopped and its device leases are released.

## Objective and scope boundary

Make physical gamepiece state, scoring/ferry/respawn mutations, and fuel contact dynamics that affect simulated behavior GPU resident. Runtime tensor predicates must stay on device; no tensor-derived CPU predicate may skip physics, change a game-rule branch, select/reset gamepieces, alter random-number consumption, change active-world state, or decide scoring/ferry/respawn outcomes. CPU may handle static configuration, Python control orchestration, and passive report/file I/O only after gameplay decisions are complete. The GPU qualifying path must fail closed if a required kernel/device path is absent; it must not silently use CPU tensor conversion, CPU broadphase, or another CPU physics fallback.

This tranche includes physical FUEL scoring and ferrying because those mutate game state and are separate from policy action-candidate generation/scoring. It covers the shared `gamepiece_actions.update_fuel_actions` path as reached from both the 3v3 and defense environments, the defense outpost-release mutation API, FUEL launch/spawn/landing allocation, both environments' gamepiece reset/preload/placement paths, physics reset/synchronization, contact collision broadphase/solver, adaptive substep control, sleep-island support logic, and gamepiece event counters that affect state. It excludes observation/perception and planner control (covered by the observation plan), policy candidate construction/ranking and PPO math (separate tranches), qualification bootstrap statistics, and unrelated chassis physics not coupled to gamepiece contacts.

## Audited callchains and gaps

1. **3v3 gamepiece tick:** `tensor_3v3.py::step` → `advance_with_fuel` → robot and FUEL physics substeps → `tensor_3v3.py::_update_fuel` → `_tensor_3v3_gamepieces.py::_update_fuel` → `gamepiece_actions.update_fuel_actions`. The action update computes active-world acquisition, possession, scoring intent, HUB timing, denial, pass/ferry, score, respawn, ownership, generation counters, and event tensors. `curriculum_scenarios.py::_update_fuel` decorates this path with scenario metrics.
2. **Defense gamepiece tick and reset:** `tensor_defense_step.py::step` → `advance_with_fuel` → `tensor_defense_gamepieces.py` update wrapper → the same `gamepiece_actions.update_fuel_actions`. Also trace `tensor_defense_reset.reset/reset_done` → `_initialize_gamepieces` and `reset_fuel_physics`; preserve different roster/control masks and event schemas while using the shared GPU state path. With `random_gamepiece_placement=True`, `_initialize_gamepieces` currently calls `nonzero(...).tolist()`, samples device random values then reads them with `.item()` for host rejection sampling, and assigns variable-length accepted positions on host. Randomized preload placement also uses device-derived boolean indexing for variable-size writes. These reset-time decisions affect piece locations, ownership/preload counts, RNG state, and later physics/policy observations. Implement fixed-shape device-mask placement and preload updates, or explicitly prohibit this configuration for any qualifying run with a fail-closed check before reset; do not allow a host fallback.
3. **Ferry/scoring respawn gates:** `gamepiece_actions.py::update_fuel_actions` uses `passed.any().item()` to skip ferry work while consuming compatibility RNG draws, and later `newly_scored.any().item()` to skip score-respawn work while consuming compatibility RNG. `fuel_physics_runtime.py::launch_fuel` independently uses `selected.any().item()` to skip selected-ball state/physics updates. These are CPU decisions based on runtime masks and directly affect policy-visible piece positions, velocities, ownership, pickup grids, scoring results, or RNG state. Replace them with fixed-shape GPU-mask updates and a versioned RNG contract.
4. **FUEL runtime physics:** `fuel_physics_runtime.py::advance_with_fuel` chooses an adaptive substep count, then interleaves robot simulation and `FuelPhysics.step`; `reset_fuel_physics`, `bind_fuel_state`, `launch_fuel`, `separate_spawned`, shooter/ferry target sampling, net-hit redirection, and `allocate_clear_ferry_spawns` update or route live game pieces. Include the defense reset initializer, randomized preload count, and random placement branch in reset-time GPU residency checks. Preserve the existing active mask, collision cadence, legal field bounds, HUB/backer-net rules, destination choice, and spawn-clearance/reservation semantics.
5. **Torch reference contact path:** `fuel_physics.py::FuelPhysics._build_pairs` tests device-derived cache-invalidating predicates on host, copies position/free tensors to CPU lists for the spatial grid, and builds variable-length pairs from host hash results. `separate_spawned` compacts contacts and branches on compacted host-visible shapes outside graph capture. `_pair_contacts`, `_torch_substep`, `_robot_contacts`, static/field contacts, sleep state, and the colored solver consume these data. `required_substeps` calls `.item()` on a device speed maximum to choose physics iteration count. The colored solver copies pairs to CPU and computes coloring in Python. These operations are behavioral physics decisions, not passive diagnostics.
6. **Optional sleep-island path:** `fuel_physics_sleep.py` copies positions, enabled masks, and candidate pairs to CPU, uses host label loops and tensor `.any()`/`.all()` decisions to form sleep islands and support stability. Either migrate this path to GPU or make it unavailable in GPU-qualifying mode with a clear fail-closed error; a configured option must not silently route to CPU.
7. **HIP path and metrics:** `fuel_physics_hip.py` plus `csrc/fuel_physics_hip.cpp`, `csrc/fuel_physics_hip_kernel.cu`, and the HIP translation unit provide device kernels. Audit every selected backend and fallback boundary against the same semantics. `refresh_stats()`/metrics materialization may remain passive reporting only if it occurs after the simulation decision and cannot influence cache invalidation, solver selection, schedule, or game state.
8. **Score event recorder:** `_capture_fuel_score_awards` in `gamepiece_actions.py` uses `nonzero(...).tolist()` and scalar `.item()` reads to write optional event records. Keep the recorder strictly downstream/passive: it may serialize already-decided awards for auditing, but its presence or CPU result must not gate scoring, respawn, simulator state, or RNG. If the GPU-only run contract prohibits these reads even for telemetry, buffer device event rows and materialize them only at an explicit non-decision reporting boundary.
9. **External outpost release API:** `TensorDefenseGamepieceMixin.release_outpost_fuel` in `tensor_defense_gamepieces.py` is callable outside the normal step and mutates live piece state. It computes `available=stock.any(-1)&selected`, then uses that device-derived boolean for advanced-index writes into position, velocity, zone, owner, and active state for each requested release. Add a fixed-shape GPU implementation using per-world device masks and masked/one-hot writes that preserves first-stock-slot ordering, per-world release counts, repeated-release behavior, and physics-state synchronization. If that API is not made device safe, an explicit qualifying-mode gate must fail closed before mutation whenever it is invoked; do not silently allow an external caller to bypass the GPU-only boundary.

Graphify architecture query confirmed the simulator→FUEL update→shared gamepiece action path and the shared `FuelPhysics` contact pipeline. Static file inspection refined the concrete host-copy and predicate sites above; treat this inventory as a lower bound and search the full reachable call graph before implementation.

## Device-resident contract

- Keep active-world masks `[N]`, per-piece masks/state `[N,P]` / `[N,P,2]`, fuel physics position/velocity/angular state `[N,P,3]`, contact masks/pairs, robot-contact impulses, reset/preload/random-placement masks and coordinates, scoring/pass/respawn masks, and event counters on the selected indexed HIP device throughout the game decision.
- Device `.any()`/`.all()`/reductions may feed device masks, device assertions/status, and fixed-shape masked tensor updates only. No `.item()`, `.tolist()`, `.cpu()`, NumPy conversion, `nonzero`-dependent host branching, or variable-length tensor shape derived from device outcomes may decide the qualifying physics path.
- Use a bounded fixed-capacity/contact-pair representation and an on-device overflow status. Overflow or unsupported shapes fail closed before producing an accepted behavior result; they cannot fall back to host pair construction.
- Preserve all active/inactive world state exactly, including reset, zero-selected launch, no-score/no-pass, sleeping, and spawned-overlap cases. Static roster size, field constants, solver selection, configured substep cap, and fixed tensor capacities may remain host metadata.
- RNG behavior is part of simulator identity. Document current dummy-draw compatibility behavior for empty pass/score masks and seeded ferry/shooter sampling. Either preserve the same draw count/order with fixed-shape device draws or increment an immutable physics/RNG implementation identity and regenerate approved seeded fixtures; never claim seed parity by assumption.
- Keep event reporting, metrics, and file writes downstream of GPU decisions. They may not be read back into the live episode control loop.

## Bounded implementation and validation sequence after approval

1. **Freeze untouched live state:** continue r4 without source, manifest, checkpoint, process, output-root, lease, or assignment changes. Use an isolated HDD worktree for all code work. Do not run tests or fixtures while r4 owns the GPUs.
2. **Complete callgraph inventory:** search both environment wrappers and every caller of `update_fuel_actions`, `advance_with_fuel`, `launch_fuel`, `FuelPhysics.step/reset`, contact pair generation, cache rebuild, adaptive substeps, spawn separation, and sleep-island helpers. Classify each tensor-derived read as gameplay/physics decision, static metadata, or passive reporting. Include conditionals based on compact tensor shapes and optional backend/configuration selection.
3. **Remove gameplay predicate gates:** eliminate the `passed.any().item()`, `newly_scored.any().item()`, and `selected.any().item()` skip branches. Use fixed-shape masked score/ferry/launch/respawn writes. Make `release_outpost_fuel` use fixed-shape per-world masks and writes, or fail closed before any mutation in qualifying mode. Preserve per-world release counts and first-stock-slot order along with score/pass ownership, HUB cooldown, robot-slot mapping, inactive rows, and deterministic random draw semantics under an explicitly versioned contract.
4. **Make reset placement and preload device safe:** migrate randomized preload generation and random gamepiece placement to fixed-shape device draws, pairwise spacing masks, bounded device-side retries, and device status; commit positions/active/owner/zone/type/preload-count state through per-world masks. Preserve deterministic seed behavior or version the RNG/source identity. If fixed-shape placement cannot be implemented and validated in this tranche, add a fail-closed qualification guard that rejects `random_gamepiece_placement=True` before any qualifying reset and rejects unsupported randomized-preload mode; diagnostic/non-qualifying behavior may remain available only when it is explicitly excluded from qualification.
5. **Move contact generation and solver control onto GPU:** replace CPU pair-grid hashing, pair compaction that controls host flow, Python colored-contact grouping, and host cache rebuild predicates with device-resident bounded structures and masks or a supported native HIP equivalent. Preserve contact ordering/equivalence where it affects the solver, equal-and-opposite impulses, overflow behavior, and pair/cache invalidation semantics. If colored or sleep-island mode cannot be implemented and verified on device, reject that configuration for qualifying execution.
6. **Remove device-scalar adaptive loop control:** replace `required_substeps().item()` and CPU loop decisions with a bounded GPU-controlled strategy. Preserve the current stability bound across fuel and robot motion; document any approved fixed maximum/substep semantic change and bind it to a new runtime/physics identity. Device-derived counts cannot be surfaced to Python to choose a loop count.
7. **Enforce fail-closed backend boundaries:** qualifying execution requires the configured indexed WX9100/HIP device and a fully GPU-resident path for gamepiece decision, collision/contact, adaptation, and state update. Missing extension, unsupported solver, overflow, mixed-device tensor, or incompatible graph-capture path must fail before stepping; no CPU fallback may produce a score, ferry, launch, or physics result.
8. **After manual r4 stop and lease release:** acquire exclusive lease(s) for the exact approved WX9100 device allocation, then run deterministic device fixtures for score/pass/no-op masks, active/inactive world isolation, shooter/ferry RNG, HUB/backer-net redirects, legal spawn reservation, empty/partial contact sets, pair overflow, cache rebuild/no-rebuild, robot/fuel/static collisions, solver modes, sleep/reset behavior, adaptive substeps, graph capture, and invalid backend/device cases. 9. **Run end-to-end simulator evaluation:** exercise acquisition, score, ferry/pass, respawn, and contact behavior in seeded scenarios; inspect the simulation record and replay and retain scenario, seed, exact source identity, physics/RNG version, and result. Do not treat unit/regression tests alone as behavioral validation.
10. **Verify dashboard before replay review:** after code changes, restart the dashboard service(s) on the exact reviewed checkout; verify service health, backend API responses, and frontend asset identity. Generate a fresh replay only after this check, inspect its provenance, and mark old-source replays outdated. Do not reuse a pre-change replay as evaluation evidence.
11. **Bind source and calibration:** this changes `frc_defense` source identity and simulator behavior. Freeze all relevant code/runtime/physics/RNG configuration before recalibrating or binding any validation protocol. Recompute source identity and checkpoint compatibility; old-source calibration, replay, report, and qualification results cannot be silently reused.
