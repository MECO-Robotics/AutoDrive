## New Pass 2 stop evidence

The previous Phase 4 profile expansion omitted the reset-time focal pose assignment. During scenario refresh, curriculum_scenarios.py::_refresh calls apply_phase4_focal_pose_assignment when a registered assignment exists. The helper is in frc_defense/meco_phase4_context.py and is therefore part of the selected reset path, not a detached evaluator-only utility.

The current helper validates a static assignment, clones simulator truth for slot 3, optionally adds a registered translation/heading offset to estimated_pose for every world, copies estimated_pose to policy_pose for every world, synchronously checks physical truth with torch.equal, builds a Python event dict, and assigns that dict to env.phase4_focal_pose_runtime. Skipping it changes the registered validation reset semantics. Calling it unmodified applies the offset and report state to unselected rows and materializes a device result on the host.

The helper's output also flows into observation generation: policy_pose is captured in the Phase 4 sensor frame, used to compute target/raster/planner anchors, and is the policy-facing pose input. The selected reset must keep the same offset-before-observation order while confining all writes and sensor-frame changes to selected worlds. The non-reset/runtime application contract is explicitly preserved; this plan only authorizes a reset-specific mask-aware path and its reset call sites.

## Masked focal reset and RNG contract

1. The reset mask is fixed shape [world], bool, on the assigned HIP device. Static assignment dictionary validation may run on host before reset orchestration because it depends only on frozen metadata; no value selected by the runtime mask or a device status may be inspected by Python.
2. For each selected world, apply the registered offset exactly once to the reset simulator-derived estimated pose, then set policy pose to that estimate. The no-offset assignment still synchronizes policy pose to estimate exactly as today. Never reapply an offset to an already-offset estimate during repeated refresh; reset-generation identity must make application idempotent within one episode reset.
3. Preserve simulator truth unchanged. The old torch.equal boolean is replaced on this reset path by a per-world device truth-preserved status tensor. A failure sets a typed device reset-failure bit and gates the whole PPO update/reset to a no-op before any parameter or optimizer mutation.
4. Preserve heading wrapping through atan2(sin, cos), registered offsets, slot 3 selection, pairing/assignment digests and applied-before-observation semantics. Do not derive pose values, status, or selected world indices through CPU materialization.
5. Selected policy pose feeds selected planner/target/raster caches and selected perception/observation. All previously specified phase-four sensor frame fields remain aligned. When history is represented by whole-batch Python dictionaries, only the selected row slices may be changed; no whole-batch list replacement or restore may alter unselected history.
6. Selected reset perception applies the same confidence cap to the same sensed values, but only for selected rows. Confidence-cap counts/reductions are device state on the reset path, with host projection deferred until passive reporting.
7. The focal transform itself consumes no randomness. Its reset implementation must not advance any RNG stream. Any selected perception refresh uses the predecessor's explicit per-world reset RNG contract and must preserve unselected perception draws/state exactly.
8. Static event identity (assignment, pair assignment, arm, offset name and config hash) may be stored once as immutable host metadata. Per-world applied/truth-preserved/failure status stays device-resident. Python report projection is passive and occurs only after device decisions, never in reset control.
9. All-false is an exact no-op including pose tensors, event/status tensors, sensor history, cap diagnostics and RNG. All-true matches current reset behavior for each registered assignment. Mixed masks match that behavior for selected rows and are strictly non-mutating for unselected rows.
10. Reset assignment schema, per-world application generation, truth-preserved status, policy pose, first-observation digest, sensor frame/cap state schema and checkpoint/source identity are versioned with the preceding reset/PPO schemas. Resume cannot double-apply or skip the assignment and must reproduce the same next observation/action.

## Acceptance and exact stop conditions

All inherited profile legality, selected-row reset and all-five PPO/candidate/route/replay/optimizer invariants must also pass their planned gates.

Stop before editing if _refresh, confidence cap, or any sensor-history helper cannot preserve unselected rows; if a Python whole-batch frame restore overwrites another row; if the offset is skipped or applied twice; if truth verification/report status requires host tensor comparison; if assignment event metadata changes qualification or policy decisions; if no-offset treatment differs from current semantics; if reset advances RNG for focal application; if the new reset path changes unmasked runtime application; if a new pose/profile/history helper is required; if an unlisted file is needed; or if any mask/status/pose/cap value reaches .item(), .tolist(), .cpu(), host hash/reduction, Python row selection, or host branch before the passive boundary. Retain all prior stop conditions: no unselected RNG/state changes, no full reset fallback, no policy/candidate/route/reward/outcome/physics/observation/PPO semantics change, no update cadence change and no campaign activity.
