## Pass 2 stop evidence and newly included gaps

Pass 2 stopped before edits after finding that the prior batched-PPO scope did not own the upstream dynamic status and candidate-selection paths needed to create a valid GPU batch:

- In frc_defense/meco_track_training.py::_run_macro_step, each tick converts done[0] and truncated[0] to Python booleans with .item() and breaks the simulator loop on the host. It also converts last action/event values to Python numbers, builds executed-action/failure-reason lists, and converts target-loss/remask flags to Python booleans. The caller stores done OR truncated as a Python bool and makes actor eligibility from a Python failure_reasons list.
- The same training caller branches on ended/timeout to clear commitments, count outcomes, increment episode/seed state, reset the environment, and clear recurrent state. A tensor status copied to the PPO row after these host branches would not close the residency gap.
- In frc_defense/meco_candidates.py::_additional_sensed_target_specs, device sorting is copied to CPU to construct dynamic Python target specifications. _build_device_candidate_set copies selected_policy and oracle_track_indices to CPU to form Python IDs/query tuples, copies the fallback scalar to host, and indexes Python specs using selected candidate order.
- frc_defense/experimental_route_evaluation.py represents live device route queries as Python DeviceRouteQuery objects and builds planner state with Python row loops over query objects. The route result keeps Python query identity/order, so a GPU-selected candidate index cannot safely gather route queries without converting that index to the host.
- These interfaces affect the actual C1/C2 and D1/D2 shared candidate path. They are not solved by the preceding PPO-only batch plan, by leaving a CPU CandidateTable beside device tensors, or by calling the single-row scorer once per Python row.

This plan explicitly expands the scope to the fixed-shape rollout status/reset boundary and the C candidate enumeration/identity/order/route-query boundary. It does not treat candidate construction or simulator terminal control as an accepted upstream CPU exception.

## Objective

Create one device-resident all-five training chain: frozen A1/A2/A3 support or C1/C2 candidate generation and selection; device route-query gathers; stochastic action/log-probability capture; fixed-shape simulator macro stepping with terminal, truncation and execution status retained as tensors; fixed-shape episode reset; typed PPO rollout rows; replay validation; GAE; and sequential Adam updates.

All numeric world state, sensor-derived candidate identities, ordering, route-query mapping, terminal/truncation predicates, rewards, status flags, actor eligibility, training loss, optimizer state, RNG progression and continuation decisions remain on the explicitly assigned HIP device. The only numeric payload crossing to host for live execution is the already-final compact action command required by the simulator dispatch boundary. Static scenario/model/config metadata and typed error/status routing may remain host-side. Passive serialization cannot affect a device decision or partial update.

## Fixed-shape lifecycle and status contract

1. **Macro ticks:** use the static configured action_ticks bound. Each env.step receives active_mask updated on-device from the accumulated terminal/truncation state and current execution-validity state. Never break on done/truncated in Python. The environment's existing tensor done/truncated outputs are the source of truth. Accumulate per-tick reward only for active ticks.
2. **Terminal state:** store terminal, truncated, transition-finished, rollout-slot-valid and bootstrap-continuation flags as separate device tensors. Preserve the current PPO bootstrap contract: the current trainer treats done OR truncated as a finished transition with zero nonterminal factor. Any correction to time-limit bootstrap semantics is a separate reviewed experiment, not this port.
3. **Execution status:** replace failure_reasons strings as control with a versioned device bitmask. Required bits cover sampled fallback, action remasking on any active tick, native goal preemption under the same event/distance predicates, selected-target loss, and selected-target/action mismatch. Compute actor_eligible from the status tensor on-device; a failed executed action contributes critic value loss and no policy/entropy loss, exactly as current behavior. Preserve all reason counts as device reductions; only format strings after update for passive reporting.
4. **Episode boundary:** terminal/truncation masks flow to the device reset routine and the PPO row without host bool conversion. Episode/reset generation counters and RNG advancement are device state. Recurrent hidden state resets under the same device mask. Reset all per-episode curriculum metrics and scenario state consistently. If the current single-world environment cannot support masked reset without a host terminal branch, this is an explicit implementation stop; do not change episode length, skip resets, or treat terminal outcomes as ordinary rollout cuts.
5. **PPO batch:** predetermined rollout slot numbers may be written by a fixed host counter. Device values, including finished masks and actor eligibility, never choose a Python list/dict slot. Padded rows are no-op for GAE, replay, RNG order, Adam parameters/moments/steps and diagnostics.

## Candidate identity, order and route contract

The tensor candidate schema carries fixed integer fields for kind, native action, sensed track buffer identity, approach variant/offset identity, continuation identity/generation, stable original row index and policy rank. A complete ordered candidate identity/digest includes all of these fields, target/goal tensors, eligibility, route-query result mapping, and the schema version. Dynamic strings such as collect:track:N are report labels only and cannot form or verify the live table.

Preserve the existing deterministic enumerator exactly: eight base action rows; one fixed row per sensed-target buffer slot, with targets outside the base top-four sorted by distance and stable buffer-index tie-break and invalid rows masked; the fixed action/approach-offset block in current order; one reserved continuation row; and the bounded oracle rows built from base plus additional sensed identities over the current 18 fixed oracle offsets. Preserve ranking: base prefix first, eligible extra targets by the canonical device order, then the fixed offset block after the count of eligible extra targets; invalid extra-capacity rows do not displace offsets. Stable sort ties preserve the present semantics. Apply K=8/16/32 policy cap and append the reserved continuation row exactly as current behavior.

Route evaluation consumes the full fixed oracle/spec tensor table or an equivalent exact fixed subset only if it preserves current candidate-recall values and feasibility outcomes. Keep candidate goals, query IDs, selection indices, route status/path/cost, candidate features and final policy order joined by device tensor indices. For more than 64 route rows, use the existing ordered chunk boundary with fixed host-known chunk spans and device global-row mapping; no selected index or route identity crosses to Python during construction. Fallback selection remains a device tensor through scoring and is gathered into the one final command payload only after the categorical choice is final.

The deterministic recall contract remains the same bounded expanded-goal oracle, not a simulator-optimality claim: preserve its oracle membership, route-feasible denominator, selected feasible numerator, no-row behavior, costs/units, tie ordering and limitations text. D1 and D2 must receive the exact same tensor candidate set, masks, route costs and risk features as C1/C2.

## Policy, optimizer, RNG, schema and checkpoint invariants

- A1/A2/A3 and C1/C2 preserve their existing stochastic masked categorical distributions, support/candidate ordering, action/log-probability pairing, hidden-state semantics, value head, PPO clip, entropy/value coefficients, advantage population/epsilon, critic-only failures, gradient clipping, per-track parameter coverage and shuffled single-transition Adam cadence.
- Batched outputs and candidate/support log probabilities match a frozen single-row reference for active rows. No batch normalization, pooling, row padding or candidate reordering may change a live distribution.
- One device permutation visits each valid transition once per epoch. A static host loop may enumerate slot positions only; a device permutation index gathers every field and no `.item()`, `.tolist()`, `.cpu()` or Python branch receives that index. The device-masked Adam transition must preserve exact active-row parameter/moment/step changes and leave invalid padding rows unchanged. If HIP autograd/Adam cannot do this, stop.
- Version the candidate identity schema, route-query batch contract, rollout status/batch schema, actor-status bits, reset/episode RNG state, checkpoint format and training source/protocol identity. Checkpoint/resume retains candidate-order counters, episode/reset state, independent device action/permutation generators, optimizer state and exact next action/order. Incompatible v1 or legacy checkpoints fail closed; no CPU-state continuation path is allowed.
- Dynamic fingerprints are computed and compared on the device before any PPO mutation. Replay/schema/device failure masks the entire update to a no-op; a typed status may stop orchestration only after the device-gated attempt. Static configuration strings can identify schema but cannot encode sensor-derived candidate values or status.
- Device identity and backend must bind to the explicitly assigned WX9100. Host may schedule work, allocate memory and read/write opaque checkpoint/artifact bytes. Host cannot compute, inspect, hash, reduce, format or validate dynamic numeric simulator/training state before the allowed final command or passive completed artifact boundary.

## Acceptance evidence and stop conditions

Accept only when source/call-graph audit proves all five tracks use the same typed device rollout contract; fixed macro ticks propagate terminal/truncation/status/reset masks without host decisions; all five distributions/replay log probabilities and sequential optimizer state match the frozen references; candidate IDs/order/recall and route queries are device-tensor-derived and preserve the deterministic reference; reset/RNG/checkpoint continuation is exact under the declared new version; and synchronization tracing shows no dynamic CPU read, conversion, list/dict selection, or numeric host computation in the qualifying path.

Stop and return to Pass 1 if any transition, truncation, target-loss, remask, preemption, fallback, reset, commitment, candidate identity/order, route query, route result, actor eligibility, PPO batch, optimizer or RNG decision needs a host scalar; if candidate support/recall differs; if fixed capacities are not proven from source bounds; if route chunks cannot reassemble exact global order; if masked reset changes unaffected state or uses host terminal branch; if active-row categorical distributions/log probabilities or sequential Adam state change; if checkpoint resume changes the next device action/permutation; if native/build/source targets outside the table are needed; or if the only viable implementation is CPU fallback, early loop exit, best-effort partial replay, policy support reduction, cadence change, or unreviewed campaign activity.

No test, simulator, device, dashboard, replay, training, fitting, evaluation, or campaign operation was performed to create this plan. This document does not assert the proposed tensor contracts or GPU residency currently exist.
