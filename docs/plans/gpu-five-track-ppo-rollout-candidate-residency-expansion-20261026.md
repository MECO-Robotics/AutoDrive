## Pass 2 stop evidence and newly included gaps

Pass 2 stopped before edits after finding that the prior batched-PPO scope did not own the upstream dynamic status and candidate-selection paths needed to create a valid GPU batch:

- In frc_defense/meco_track_training.py::_run_macro_step, each tick converts done[0] and truncated[0] to Python booleans with .item() and breaks the simulator loop on the host. It also converts last action/event values to Python numbers, builds executed-action/failure-reason lists, and converts target-loss/remask flags to Python booleans. The caller stores done OR truncated as a Python bool and makes actor eligibility from a Python failure_reasons list.
- The same training caller branches on ended/timeout to clear commitments, count outcomes, increment episode/seed state, reset the environment, and clear recurrent state. A tensor status copied to the PPO row after these host branches would not close the residency gap.
- In frc_defense/meco_candidates.py::_additional_sensed_target_specs, device sorting is copied to CPU to construct dynamic Python target specifications. _build_device_candidate_set copies selected_policy and oracle_track_indices to CPU to form Python IDs/query tuples, copies the fallback scalar to host, and indexes Python specs using selected candidate order.
- frc_defense/experimental_route_evaluation.py represents live device route queries as Python DeviceRouteQuery objects and builds planner state with Python row loops over query objects. The route result keeps Python query identity/order, so a GPU-selected candidate index cannot safely gather route queries without converting that index to the host.
- These interfaces affect the actual C1/C2 and D1/D2 shared candidate path. They are not solved by the preceding PPO-only batch plan, by leaving a CPU CandidateTable beside device tensors, or by calling the single-row scorer once per Python row.

This plan explicitly expands the scope to the fixed-shape rollout status/reset boundary and the C candidate enumeration/identity/order/route-query boundary. It does not treat candidate construction or simulator terminal control as an accepted upstream CPU exception. Its device command and record contract remains blocked by the upstream plans pinned below; it cannot close any of the five Stage 1 gates A1, A2, A3, C1 or C2 on its own.

## Objective

Create one device-resident all-five training chain: frozen A1/A2/A3 support or C1/C2 candidate generation and selection; device route-query gathers; stochastic action/log-probability capture; fixed-shape simulator macro stepping with terminal, truncation and execution status retained as tensors; fixed-shape episode reset; typed PPO rollout rows; replay validation; GAE; and sequential Adam updates.

All numeric world state, sensor-derived candidate identities, ordering, route-query mapping, terminal/truncation predicates, rewards, status flags, actor eligibility, training loss, optimizer state, RNG progression, selected actions, and continuation decisions remain on the explicitly assigned HIP device. No selected action, local/source-global row, candidate identity, log probability, route field, execution result, or derived numeric value crosses to Python for live dispatch. The native tensor/HIP simulator consumes the selected device action/goal/target tensors and returns fixed-shape device state/status. Host work is compute-free scheduling, allocation, kernel dispatch, immutable configuration handling, typed error/control routing within the whole-compute authority, and byte-for-byte I/O of complete device-produced opaque record bundles. No host formatter, decoder, digest, aggregation, metric, or numeric validity gate is allowed. Passive serialization cannot affect a device decision or partial update.

## Canonical PPO transition and existing replay-record v2

Define one fixed-capacity `FiveTrackPpoTransitionV3` row inside `FiveTrackPpoBatchV3`. This row is the sole per-decision record for A1/A2/A3/C1/C2 training rollout and evaluation replay. It replaces the current schema-v1 PPO replay row and the v1 executed-policy trace within their existing canonical training/evaluation replay artifacts; it is not a diagnostic sidecar or parallel route record. The record owner serializes the complete dynamic bundle into a device-produced opaque byte buffer. Host writes that buffer unchanged to the existing canonical artifact locations. If the current JSON/Torch containers cannot carry the raw device bytes without host decoding or re-encoding dynamic values, migrate those canonical containers to a versioned binary v2 envelope at the same logical artifact locations. Do not add an alternate path, secondary artifact, shadow trace, CPU JSON formatter, host-generated checksum, or duplicate digest.

Each transition row must bind these values from the same on-device decision and simulator execution:

1. **Decision identity and source support:** static track/model/protocol IDs; fixed rollout slot, rollout generation, episode generation and decision ordinal; input/state provenance; complete ordered A support or C source-table identity/digest; and per-track support/candidate validity.
2. **Action identity and probability:** A stores both the policy-local support index and its mapped source support row (`node`, `behavior`, `descriptor`); C stores the policy-local selected index and its separate mapped source-global row. For C, ordinary local slots `0..K-1` map through `ordinary_row_map[j]=selected_policy[j]` and local continuation K maps through `continuation_row_map[0]=continue_index`, including non-prefix global rows for K=16/32. The mapped source row binds the exact existing v2 descriptor identity corresponding to that candidate, action, track, goal and route; preserve legacy candidate-label semantics for v1 history/display, but never put a dynamic label into live training or infer identity from the policy-local index/action code. Record the exact selected action tensor and old log-probability tensor in the declared model dtype, predecision logits/distribution digest as required by the frozen PPO parity contract, and device RNG stream/counter before and after sampling. The same mapping determines the selected action, log probability, simulator command and replay row.
3. **Route and macro execution:** route query/source-global mapping, result status/feasibility, cost units/value, selected path/length and device route fingerprint; macro start/end ticks; active-mask/per-tick action; action remask, native preemption, target loss, fallback and completion status bits; device-produced next observation/world-state binding; reward/value/terminal/truncation/bootstrap fields. Simulator output and execution status must refer to the same chosen device action and source-global row captured in (2).
4. **PPO masks and recurrent/reset state:** actor-eligibility and critic-validity masks derived on-device from the recorded execution-status bits; preserve critic-only updates for failed/remasked actions. Record recurrent hidden state before/after, recurrent reset mask/reason, episode reset mask/generation, per-slot terminal/truncation flags and exact next RNG/counter state. Keep reward/GAE bootstrap semantics, optimizer cadence/order and checkpoint continuation as specified below.
5. **Replay determinism:** before any PPO mutation, replay regenerates the same source support/candidate table and row maps, route-query binding, logits/distribution, sampled local/global index, exact selected action/log-probability, RNG progression, actor/critic masks, macro/execution evidence, recurrent/reset state and provenance on device. Compare device-generated fingerprints/status. Any mismatch gates the entire update to a no-op; no host scalar or parsed record field may select which transition or parameter update proceeds.

`FiveTrackPpoBatchV3` is a fixed `R`-slot tensor structure; each field below has a batch dimension R and a source-bounded static tail shape, never a Python list of per-row maps. In each valid `FiveTrackPpoTransitionV3` row: (i) `track_id`, policy/input/protocol schema IDs, rollout slot/generation, episode generation and decision ordinal bind the fixed slot; (ii) A's policy-local support choice and mapped source support row, or C's `policy_local_index` and `source_global_row`, are separate signed 64-bit indices, with C's ordinary and continuation maps retained or reproducibly bound by their device digest; (iii) the source-ordered support/candidate identity digest and selected A support descriptor or C v2 candidate descriptor are fixed-width device-produced bytes; (iv) selected action index is an integer tensor and `old_logprob`/old value retain the exact model-declared floating dtype, with categorical RNG stream ID and before/after counters as device integer tensors; (v) reward, terminal, truncated, transition-finished, bootstrap-continuation and rollout-valid are separate device scalars; (vi) actor-eligibility, critic-validity and execution-status are device masks/bit fields; (vii) route schema ID, query/source-global row binding, route status/feasibility/cost units and fixed-capacity route path/length use the route owner's declared types; (viii) action-tick active mask, action, remask/preemption/target-loss/fallback bits and macro start/end/result use fixed `action_ticks` capacity; (ix) post-macro policy observation and required simulator output fields use their registered fixed shapes, with a device-produced state/replay fingerprint; and (x) recurrent hidden state before/after, reset mask/reason, episode-reset generation, next RNG counter, checkpoint/model/source provenance are device fields or immutable static header fields. Invalid/padded R slots are all-zero/no-op according to schema and cannot advance RNG, GAE, replay or optimizer state. Capacity/dtype must be pinned in the implementation manifest from reviewed source bounds; if any field requires dynamic host sizing, stop for Pass 1.

The binary v2 envelope starts with static magic/version/schema/capacity identifiers and then the fixed batch payload. The complete envelope, including any dynamic digest/status bytes and selected-action trace, is produced on-device as opaque bytes. The host may allocate the path and write those bytes unchanged; it may not build the envelope header from tensor values, encode JSON, tensor-to-CPU copy, hash, validate, or decode the payload. The layout reuses the existing PPO/replay logical records and v2 trace field; it is not an additional route ABI.

The existing PPO replay `schema_version=1` rows and `executed_policy_decision_trace_schema` / `meco-executed-policy-decision-v1` evaluation records remain read-only historical compatibility. New source writes only v2 into those existing canonical training/evaluation artifact locations: outer replay `schema_version=2`, `meco-executed-policy-decision-v2`, and (for evaluation) an embedded opaque `executed_policy_decision_trace` byte region bound to `FiveTrackPpoTransitionV3`; never downgrade, relabel, rewrite or use v1 as current-source qualification evidence. The v2 byte region is embedded in the same canonical artifact, not a pointer or detached route trace. If v1 JSON/Torch containers cannot safely hold it, each canonical artifact container becomes a versioned binary v2 envelope at that same logical location; paths may not fork into a shadow or sidecar. Existing dashboard/replay consumers must reject v2 until upgraded under the separate reviewed display boundary; their v1 readers remain available for historical artifacts. New v2 replay presentation may identify itself as `dashboard-replay-generation-v2` only after that display boundary is approved.

The display reader is allowed only after an explicit whole-compute amendment and exact-head independent Pass 3 review. It may parse the completed v2 bytes to render recorded action/route/execution/recurrent provenance to a human, but cannot feed training, route or action choice, replay validation, evaluation metrics, campaign sealing, qualification, readiness, status gates, artifact hashes, or PPO replay verdicts. If that exception is not accepted, v2 dashboard replay review remains unavailable; do not weaken the GPU-only boundary or emit host-decoded values to satisfy it.

## Fixed-shape lifecycle and status contract

1. **Macro ticks:** use the static configured action_ticks bound. Each env.step receives active_mask updated on-device from the accumulated terminal/truncation state and current execution-validity state. Never break on done/truncated in Python. The environment's existing tensor done/truncated outputs are the source of truth. Accumulate per-tick reward only for active ticks.
2. **Terminal state:** store terminal, truncated, transition-finished, rollout-slot-valid and bootstrap-continuation flags as separate device tensors. Preserve the current PPO bootstrap contract: the current trainer treats done OR truncated as a finished transition with zero nonterminal factor. Any correction to time-limit bootstrap semantics is a separate reviewed experiment, not this port.
3. **Execution status:** replace failure_reasons strings as control with a versioned device bitmask. Required bits cover sampled fallback, action remasking on any active tick, native goal preemption under the same event/distance predicates, selected-target loss, and selected-target/action mismatch. Compute actor_eligible from the status tensor on-device; a failed executed action contributes critic value loss and no policy/entropy loss, exactly as current behavior. Preserve reason counts as device reductions within the record. Do not format dynamic counts or reasons on host; a separately approved non-gating display reader may render completed opaque records for a human.
4. **Episode boundary:** terminal/truncation masks flow to the device reset routine and the PPO row without host bool conversion. Episode/reset generation counters and RNG advancement are device state. Recurrent hidden state resets under the same device mask. Reset all per-episode curriculum metrics and scenario state consistently. If the current single-world environment cannot support masked reset without a host terminal branch, this is an explicit implementation stop; do not change episode length, skip resets, or treat terminal outcomes as ordinary rollout cuts.
5. **PPO batch:** predetermined rollout slot numbers may be written by a fixed host counter. Device values, including finished masks and actor eligibility, never choose a Python list/dict slot. Padded rows are no-op for GAE, replay, RNG order, Adam parameters/moments/steps and diagnostics.

## Candidate identity, order and route contract

The tensor candidate schema carries fixed integer fields for kind, native action, sensed track buffer identity, approach variant/offset identity, continuation identity/generation, source-global row index and policy rank. Policy-local indices address only model utility/action outputs; source-global indices address the full per-decision candidate source table and its ordered descriptor/ID/feature/route/action/goal/track columns. For C, `ordinary_row_map[j]` is `selected_policy[j]` for local ordinary `j∈[0,K)`; these may be non-prefix source rows at K=16/32. `continuation_row_map[0]` is source-global `continue_index` for local continuation K. All candidate feature/map gathers, selected descriptor/ID binding, route/action gathering, table digest, transition selected-global-row field and replay identity use the source-global index after the device map. A complete ordered candidate identity/digest covers the source-global table order, all descriptor fields, target/goal tensors, eligibility, route-query result mapping and schema version. Dynamic strings such as collect:track:N are labels for the approved human display reader only; they cannot form or verify the live table or PPO record on host.

Preserve the existing deterministic enumerator exactly: eight base action rows; one fixed row per sensed-target buffer slot, with targets outside the base top-four sorted by distance and stable buffer-index tie-break and invalid rows masked; the fixed action/approach-offset block in current order; one reserved continuation row; and the bounded oracle rows built from base plus additional sensed identities over the current 18 fixed oracle offsets. Preserve ranking: base prefix first, eligible extra targets by the canonical device order, then the fixed offset block after the count of eligible extra targets; invalid extra-capacity rows do not displace offsets. Stable sort ties preserve the present semantics. Apply K=8/16/32 policy cap and append the reserved continuation row exactly as current behavior.

Route evaluation consumes the full fixed oracle/spec tensor table or an equivalent exact fixed subset only if it preserves current candidate-recall values and feasibility outcomes. Keep source-global candidate goals, query IDs, policy-local/source-global row maps, route status/path/cost, candidate features and final policy order joined by device tensor indices. For more than 64 route rows, use the existing ordered chunk boundary with fixed host-known chunk spans and device global-row mapping; no selected index or route identity crosses to Python during construction. Fallback selection remains a device tensor through scoring and supplies the same native device simulator command interface only after categorical choice is final; it is never gathered into a host payload.

The deterministic recall contract remains the same bounded expanded-goal oracle, not a simulator-optimality claim: preserve its oracle membership, route-feasible denominator, selected feasible numerator, no-row behavior, costs/units, tie ordering and limitations text. D1 and D2 must receive the exact same tensor candidate set, masks, route costs and risk features as C1/C2.

## Policy, optimizer, RNG, schema and checkpoint invariants

- A1/A2/A3 and C1/C2 preserve their existing stochastic masked categorical distributions, support/candidate ordering, action/log-probability pairing, hidden-state semantics, value head, PPO clip, entropy/value coefficients, advantage population/epsilon, critic-only failures, gradient clipping, per-track parameter coverage and shuffled single-transition Adam cadence.
- Batched outputs and candidate/support log probabilities match a frozen single-row reference for active rows. No batch normalization, pooling, row padding or candidate reordering may change a live distribution.
- One device permutation visits each valid transition once per epoch. A static host loop may enumerate slot positions only; a device permutation index gathers every field and no `.item()`, `.tolist()`, `.cpu()` or Python branch receives that index. The device-masked Adam transition must preserve exact active-row parameter/moment/step changes and leave invalid padding rows unchanged. If HIP autograd/Adam cannot do this, stop.
- Version the candidate identity schema, route-query batch contract, rollout status/batch schema, actor-status bits, reset/episode RNG state, checkpoint format and training source/protocol identity. Checkpoint/resume retains candidate-order counters, episode/reset state, independent device action/permutation generators, optimizer state and exact next action/order. Incompatible v1 or legacy checkpoints fail closed; no CPU-state continuation path is allowed.
- Dynamic fingerprints are computed and compared on the device before any PPO mutation. Replay/schema/device failure masks the entire update to a no-op; a typed status may stop orchestration only after the device-gated attempt. Static configuration strings can identify schema but cannot encode sensor-derived candidate values or status.
- Device identity and backend must bind to the explicitly assigned WX9100. Host may schedule work, allocate memory and read/write opaque checkpoint/artifact bytes. Host cannot compute, inspect, hash, reduce, format or validate dynamic numeric simulator/training state before the allowed final command or passive completed artifact boundary.

## Acceptance evidence and stop conditions

Accept only when source/call-graph audit proves all five tracks use the same typed device rollout contract; fixed macro ticks propagate terminal/truncation/status/reset masks without host decisions; all five distributions/replay log probabilities and sequential optimizer state match the frozen references; candidate IDs/order/recall and route queries are device-tensor-derived and preserve the deterministic reference; reset/RNG/checkpoint continuation is exact under the declared new version; and synchronization tracing shows no dynamic CPU read, conversion, list/dict selection, or numeric host computation in the qualifying path.

Stop and return to Pass 1 if any transition, truncation, target-loss, remask, preemption, fallback, reset, commitment, candidate identity/order, route query, route result, actor eligibility, PPO batch, optimizer or RNG decision needs a host scalar; if candidate support/recall differs; if fixed capacities are not proven from source bounds; if route chunks cannot reassemble exact global order; if masked reset changes unaffected state or uses host terminal branch; if active-row categorical distributions/log probabilities or sequential Adam state change; if checkpoint resume changes the next device action/permutation; if native/build/source targets outside the table are needed; or if the only viable implementation is CPU fallback, early loop exit, best-effort partial replay, policy support reduction, cadence change, or unreviewed campaign activity.
