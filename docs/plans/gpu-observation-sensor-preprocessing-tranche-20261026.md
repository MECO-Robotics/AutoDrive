# Pass 1 plan: GPU-resident observation, sensor, reset, and step control

**State:** implementation plan only; static source review, no code/runtime changes.  
**Reviewed base:** `53f3d9c9a49a7e12bf65b5e1fa2797f4464e63be`.  
**Execution constraint:** the live diagnostic r4 campaign remains untouched and uninterrupted. Defer fixtures, GPU/device checks, profiling, and simulator evaluation until r4 is manually stopped and both WX9100 leases are released.

## Objective and boundary

Make the simulator observation and sensor-preprocessing data that feeds policy inputs GPU resident from active-world selection through perception/tracking, reset placement, per-step planner/override masks, observation assembly, normalization, and the returned observation tensor. Device masks and tensors must determine all per-world/per-robot work. No CPU read of a tensor predicate may branch, compact, choose, or alter policy-visible values, reset placement, planner execution, or reported execution-failure state.

This tranche covers `_tensor_3v3_observation` active-world sampling/branching, the `observation.py` NumPy normalization adapter, `tensor_3v3.step`, `tensor_defense_step.step`, `tensor_physics.TensorSim.step/_step_eager`, active-count and active-nonempty producer/caller contracts, `tensor_defense_reset` endpoint sampling/placement/reset paths, `tensor_3v3.reset_done`, `tensor_physics.TensorSim.reset_done` and `_randomize`, and the per-step planner/optional-override/reporting masks in `tensor_3v3.step`, as well as `tensor_sim.py`/`tensor_defense_observation.py` perception and observation callsites feeding policies. Preserve the existing AD* route algorithm; this scope is its active-mask, replan, retry, override, and output-control plumbing only. Candidate generation/scoring and PPO optimization/update math remain separate. The narrow trainer-runtime boundary is included only to audit `_active_count` producers and ensure they do not copy device predicates to host; broad PPO trainer-loop restructuring remains separate. Static configuration such as robot roles, fixed capacities, and field dimensions may remain host metadata; values read from runtime device masks may not drive host control flow.

## Source callchains in scope

1. **3v3 policy observation:** `tensor_3v3.py::reset/step` → `_tensor_3v3_observation.py::_update_perception` → sensor detections, anonymous tracking, and opponent tracking → `observe(active_mask)` → `[world, robot, 137]` observation tensor. This is the primary six-robot policy observation path.
2. **Defense/strategic observation and reset:** `tensor_defense_step.py::step` → `tensor_defense_observation.py::_update_perception`, `_raw_obs`, `_strategic_observation`, `_obs` → policy observation history and current state. Include `tensor_defense_reset.py::_sample_episode_endpoints`, `_move_adstar_defenders_to_clear_start`, `_place_defenders_near_clear_adstar_paths`, and `reset_done`. Reset zone validation, unresolved placement fallback, defender retry termination, and `bool(mask.all().item())` planner cadence all consume runtime tensor predicates. Keep endpoint legality, separation preference, fixed per-world reset behavior, and planner cadence intact using device masks/status.
3. **Normalization:** `observation.py::normalize_numpy_observation_in_place` is a separate NumPy path; `normalize_tensor_observation_batch_in_place` is the torch path used by both observation mixins. Policy-facing normalization must use a device-resident tensor implementation with the same fixed scales and clamps.
4. **Sensor kernels and observation prototypes:** `tensor_perception.py`, `tensor_strategic_observation_proto.py`, and `tensor_strategic_observation_full_proto.py` are called from the above paths. Keep their observation-visible intermediate tensors on the selected device; any optional extension/prototype selection must be static capability/configuration, not a data-dependent host predicate. If an extension cannot satisfy the device contract, fail closed for the GPU-only qualifying path rather than silently switching to a host observation implementation.
5. **Active-count boundary:** audit `tensor_3v3.step` and `tensor_defense_step.step`, their `_active_count` arguments, and every caller. In particular, inspect `tensor_training_runtime.py` (known horizon schedule, `remaining_ticks.detach().cpu()` reduction, and fallback `active_this_decision.sum().item()`) and `tensor_training_evaluation.py` (`active_episode_count` is scheduler-known and forwarded for strategic calls). Remove any device-mask reduction/copy used to choose host branches; caller-provided counts are permitted only when already known as static/scheduler shape metadata, otherwise retain the full device mask and use fixed-shape masked tensor operations. This does not authorize unrelated PPO optimization changes.
6. **Physics active-mask and reset boundary:** both policy step paths call `advance_with_fuel` and then `env.sim.step`. `TensorSim._step_eager` currently checks `bool(active_mask.any())` for an early return unless `_active_nonempty` is asserted; audit `tensor_3v3.step`'s `active_count>0` producer and all `advance_with_fuel` forwarding/default/graph-capture callers. This hint may be trusted only when supplied as host-known shape/scheduler metadata; it cannot be derived from a device mask. Prefer fixed-shape physics work with device-masked state updates so empty and partial masks preserve exact semantics without a host predicate. Both `tensor_3v3.reset_done` and `tensor_defense_reset.reset_done` call into `TensorSim.reset_done`; trace both reset callchains through `TensorSim.reset_done` and `_randomize`, including their reset-mode/nominal callers. `reset_done` currently uses `int(mask.sum().item())` to choose sample shape/branch, and `_randomize` repeats the mask-derived count to size random draws and select reset parameters. These decisions must become fixed-shape device-mask operations. Preserve per-world reset semantics, nominal-vs-random parameter selection, and deterministic RNG/state progression for active/inactive worlds; if the random draw sequence changes, version runtime/source identity and regenerate compatible fixtures after device release.
7. **3v3 step planner and override control:** `tensor_3v3.step` builds planner masks and optional selected-target, goal-heading, and learned-traversal overrides around the existing AD* calls. Audit its runtime-mask reads and host conversions. `active.any()` gates audit flags later consumed by macro-step execution-failure handling; partial `flat_active.any()` sets `replan_due`; override eligibility reads active and override masks on host; `selected[3]` and `flat_active[3]` gate override application and metadata; eager `retry_flat.any()` controls retry planning; and heading-mask `.any()` controls route-alignment behavior. Preserve these outcomes as device state/masks and keep the route algorithm unchanged. Static request metadata (track index, configured goal-action pairing, traversal-request version/scale) may still be checked on host if not derived from tensor values. The minimal `_run_macro_step` handoff for target-valid/action-match flags is included: carry device boolean status into failure/remasking masks, and materialize it for passive reporting only after the step decision; do not use Python `is False` on a tensor-derived status.
8. **Policy handoff:** `env.observe()` and `_obs()` return device tensors consumed as `_last_obs` by policy decision code. This tranche ends at that tensor boundary. Action candidate construction/scoring and PPO update math are outside scope.
9. **Explicit blocking gameplay dependency outside this tranche:** `tensor_3v3.step` → `_update_fuel` in `_tensor_3v3_gamepieces.py` → `gamepiece_actions.update_fuel_actions` → `fuel_physics_runtime.launch_fuel` remains a separate simulator/gamepiece-physics residency tranche. `update_fuel_actions` currently branches on `passed.any().item()` and `newly_scored.any().item()` to skip ferry/scoring respawn work and preserve RNG; `launch_fuel` branches on `selected.any().item()` to skip physics updates. These predicates affect FUEL scoring/ferry respawn and policy-visible game state. They are deliberately excluded here, and this plan's acceptance proves residency only for the enumerated observation/sensor/reset/planner paths, not the complete simulator callchain or whole-compute GPU-only requirement. The separate tranche must remove or replace these host decisions and audit adjacent event/control and fuel-physics predicates before a qualifying simulator run.

## Current issues to resolve

- `_tensor_3v3_observation.py::_random_active` computes `int(active.sum().item())` when `active_count` is absent, then uses that host count to allocate a compact random tensor. This creates a device synchronization and a data-dependent host branch. The active mask must remain a device tensor; random draws and masked writes need a GPU-only design.
- `tensor_3v3.step` computes `active_count` with `int(active.sum().item())` when `_active_count` is absent, and its later sensor-update path computes `int(update_active.sum().item())`. `tensor_defense_step.step` similarly extracts `int(active_mask.sum().item())`. These counts control early returns, planner full-batch modes, perception sampling, and observation paths. Replace these with device-masked/fixed-shape behavior; do not repair only `_random_active` while leaving step-level host predicates.
- `_obs` and 3v3 `observe` include Python branches such as partial-batch checks and first-frame logic. Represent runtime decisions as tensor masks/selects; use only caller-known static initialization metadata for unavoidable shape branches. Do not call `bool(active.all())` or materialize a device predicate for host control flow. `tensor_defense_observation.py::_random_active` also extracts `.sum().item()` when no count is supplied. Remove this fallback; fixed-shape draws and device masking must support the no-count path.
- `observation.py::normalize_numpy_observation_in_place` has host scalar/list arithmetic, and may be used by NumPy adapters. Keep it for explicit offline/CPU compatibility if necessary, but exclude it from qualifying GPU policy paths. GPU validation must prove the active policy callchain uses only the tensor normalizer.
- `tensor_physics.TensorSim.reset_done` uses `int(mask.sum().item())` to choose sample shape/control flow, and `_randomize` repeats that host-derived count to choose draw shape and reset physics parameters. Both are called from reset paths and therefore affect policy-visible state. Keep reset masks, randomization parameters, and writes fixed-shape/device-resident; preserve each world's existing reset semantics and RNG/state progression, or explicitly version any changed RNG contract.
- `tensor_physics.TensorSim._step_eager` uses `bool(active_mask.any())` for a host early return. On the five-track callchain, `tensor_3v3.step` passes `_active_nonempty=active_count>0` through `advance_with_fuel` to `TensorSim.step`; because the count can itself be mask-derived this does not remove the predicate. Other `_active_nonempty` callers include `advance_with_fuel` forwarding its hint to eager steps and its graph capture, plus `TensorSim.step` compile-path internal assertions. Eliminate tensor-derived early return/claims, and ensure empty/partial masks retain the exact physics state-update semantics using device masks.
- `tensor_defense_reset.py::reset_done` computes `full_reset=bool(mask.all().item())`, then uses that host predicate to restore scalar planner cadence. `tensor_3v3.reset_done` similarly branches on `bool(mask[0])` and `bool(mask.all())` to reset signatures and planner scalar cadence. Replace both with per-world device state or a separately supplied caller-known reset mode; a runtime mask may not be copied to decide whether scalar fast-path state changes. If those scalar optimizations cannot be kept GPU resident, disable them for this path and use per-world tensor cadence.
- `tensor_defense_reset.py` also branches on device-derived zone validity/equality (`zones.any`, `same.any`, `start_zone == goal_zone`), unresolved endpoint fallback (`unresolved.any`), legal-point feasibility (`has_legal_point[unresolved].all`), and defender relocation retry completion (`needs_move.any` break). Use fixed iteration counts, device `where`/masks and a GPU-side fail-closed status for impossible layouts. Preserve legal endpoint selection, the existing 3 m preference relaxation rule, collider clearance, and reset placement; do not perform host rejection sampling decisions. This includes predicates in the random lattice fallback and placement retries, not just `reset_done` full-reset detection.
- `tensor_3v3.step` has additional runtime-derived host branches: `if bool(active.any())` guards target-valid/action-match audit values that `_run_macro_step` later treats as target-loss/remasking failure; `bool(flat_active.any())` controls partial-batch replanning; traversal override eligibility consumes `active[0]` and `planner_goal_override_mask[0,3]`; scalar `selected[3]`/`flat_active[3]` reads affect override application and focal-planned bookkeeping; `retry_flat.any()` gates eager retry planning; and heading-mask `.any()` gates route-turn control. `aging_active.any()` and `update_count` also branch on active sensor masks to skip aging/perception updates. The `replan_due` branch also consumes these decisions. Replace tensor reads with device predicates and masked/fixed-shape calls while preserving exact active rows, retries, audit/failure flags, and planner state. Preserve `selected_target_lost` and `selected_target_action_remasked` as device masks through the narrow `_run_macro_step` handoff so the host does not branch on tensor-derived Python booleans.
- Tensor validation on optional goals, headings, traversal-cost maps and override masks also currently converts device results to Python booleans/scalars (finite/nonnegative checks, goal bounds, signature goal values, forced-replan validity). Keep static host argument/schema validation, but validate tensor data with device assertions/status and avoid converting goal coordinates or mask results to host control values. On missing device assertion support, fail closed before qualifying execution. Audit all tensor-derived predicates in these step/reset helpers, including `bool(torch.isfinite(...).all())`, `.any().item()`, `float(goal[i])`, `goal.detach().cpu().tolist()`, and `bool(mask[0])`; this list is a minimum callsite inventory, not permission to leave equivalent conversions elsewhere.
- The observation/perception code contains static Python branches over configured control modes/roles and feature availability, plus host flags returned by optional kernels (`fused_tracks`, `fused_opponents`). Classify each: static configuration/capability branching can remain; runtime tensor outcomes must be applied through device masks and cannot decide host execution or skip required work. Existing CPU-specialized visibility paths must not be used by qualifying GPU execution.

## Device-resident shape and control contract

- Active/reset/planner-selected rows: boolean tensors on `env.device` (`[N]` for worlds, `[N,6]` or flattened `[N*6]` for robots). Device reductions such as `.any()`/`.all()` are allowed only when the resulting predicate stays on device and feeds tensor masks/assertions; no conversion of these results to Python bool/int, `.item()`, `.tolist()`, `.cpu()`, or NumPy may control a host branch in qualifying execution.
- 3v3 observation output: floating tensor `[N, 6, 137]` on `env.device`; `OBS_DIM=137`. Row updates and preservation of inactive worlds use tensor `where`/masked writes.
- Sensor visibility and anonymous detections: device masks such as `[N, 6, F]` or configured camera-expanded forms; positions/velocities `[N, 6, F, 2]` (or their documented camera/observer-expanded tensors), with validity, confidence, extents, and merge markers aligned on the same device.
- Track state: bounded position/velocity `[N, 6, F, 2]`, age/confidence/validity `[N, 6, F]`; opponent estimates `[N, 6, ...]`. Association, one-to-one collision resolution, stale-track expiration, and active-world commits must be tensor operations on `env.device`.
- Defense raw observations: fixed schema batches `[N, 35]` or the configured strategic width, normalized in place by the tensor normalizer. History writes/merges use device indices/masks and preserve inactive rows.
- Configuration values (e.g. fixed robot count, static mode tuple, field extents, model capacity) may be host scalars. `_active_count` may remain only as known shape metadata already available from a static scheduler contract; audit all callers and prohibit deriving it from a device mask, including `.sum().item()` or `.detach().cpu()` reductions. No-count paths must remain correct using fixed-shape draws and device masking. Step early-return/full-batch behavior must not branch on a count derived from runtime tensors.
- Preserve sensor RNG determinism as an explicit contract. If fixed-shape device draws change random consumption relative to compact active-only draws, version the observation/runtime identity and regenerate compatible seeded fixtures after device release; do not silently claim seed parity.
