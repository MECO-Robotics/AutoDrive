## Decision: two K-width score views, K+1 device-side selectable options

The approved candidate semantics are **K ordinary policy-ranked candidates followed by one optional dynamically revalidated continuation candidate**. Thus there are K+1 selectable options when continuation is valid. Do not reserve a slot by dropping the Kth ordinary candidate. At the same time, the Plan C model input contract caps each candidate-feature view at exactly `[1,K,40]`, where K is 8, 16, or 32. No model input tensor may include inactive extras, expanded offset rows beyond the ordinary K-prefix, or recall-oracle rows.

Resolve the width/set mismatch using two explicit, aligned device score views in one versioned C1/C2 request:

1. `ordinary_features: float [1,K,40]`, `ordinary_valid_mask: bool [1,K]`, and `ordinary_row_map: int64 [1,K]` represent the stable, eligibility-filtered ordinary policy prefix. This is the only view that establishes the C2 candidate context.
2. `continuation_features: float [1,K,40]`, `continuation_query_mask: bool [1,K]`, and `continuation_row_map: int64 [1,K]` represent only the optional continuation query in slot 0; all remaining slots are inert masked padding with a sentinel row map. If no continuation is valid, the whole view is masked and no continuation utility is accepted.
3. C1/C2 return `ordinary_utility: float [1,K]` and `continuation_utility: float [1,1]`; uncertainty outputs have matching widths. Hidden state has the existing `[1,64]` shape and is produced once. The post-model policy layer concatenates utility/uncertainty on device into K+1 entries; this output/selection vector is not a model input view and never crosses to host.
4. C2 encodes ordinary features and computes the masked ordinary query mean once; its GRU updates hidden state once from the existing global state plus this prefix-only pooled context. The continuation feature is then encoded and cross-attended to the same map tokens, fused with the **already computed ordinary-prefix GRU state**, and scored with the same scorer/uncertainty heads; it must not invoke the GRU again or replace/augment the shared context. Thus no second candidate context is recomputed for the continuation. If there are zero valid ordinary rows, use an all-zero pooled candidate contribution and still apply the existing global/hidden recurrent update; masked reduction must remain finite. C1 has no candidate-pooled recurrent context: use the same C1 candidate encoder/scorer parameters and the same global/hidden state for ordinary and continuation query views, producing the continuation score independently without consuming an ordinary slot. In each view, active rows occupy a canonical prefix; continuation is active only at slot 0. Pad unused feature rows with finite zeros, set their masks false and row maps to fixed sentinel `-1`. If no continuation exists, all continuation mask entries are false and its utility is excluded. If no ordinary row and no continuation are valid, take the established typed no-feasible/fallback path without sampling an invalid index. These are explicit model-context amendments to the prior all-row K+1 C2 mean pool; they preserve the selectable candidate set and are subject to Pass 3 behavioral review. If Pass 3 finds the shared-context/two-query contract cannot be implemented without wider feature tensors or CPU transfer, stop for a new product decision rather than shrink the prefix or widen input.
5. After scoring, selection uses the exact established ordered set: local indices `0..K-1` identify ordinary rows in approved eligibility-filtered rank order; local index `K` identifies continuation. For device-selected local index `j`, select `ordinary_row_map[j]` when `j<K`, otherwise `continuation_row_map[0]`, using device predicates/gather only. Gather global-table action, route, goal, target and provenance by that global row. Mask padded entries and invalid continuation with `-inf` before argmax/categorical selection. Deterministic ties select the lowest valid local index, so ordinary rows precede continuation on equal utility. Stochastic selection samples the same masked K+1 categorical distribution and records that selected local index's exact log probability; no host-side index conversion is allowed. Preserve deterministic fallback, commitment revalidation and switch-cost semantics.

This makes the distinction explicit: **K is the ordinary policy-prefix/model-view width; continuation is the approved appended slot with its own K-width padded query view; the policy selection width is K+1 when continuation is present.** The route/recall pool may be larger, but only the K ordinary prefix and one continuation query may participate in C1/C2 computation. This is a deliberate Plan C model-context amendment: C2's recurrent state sees the valid ordinary K-prefix only; the continuation is scored against that same state and is not added to the shared context pool. This preserves the K ordinary choices, appended continuation choice, and shared context across candidate utilities, while making the previously implicit K+1 pooled-context behavior explicit and replaceable under the exact K-view cap. It does not assert bitwise equivalence with the old context.

## Static identity, dynamic mapping, and protocol migration

Add a discriminated C1/C2 candidate-view protocol (for example `plan-c-k-prefix-plus-continuation-v2`). Do not infer this protocol from tensor shapes or weaken the legacy `MecoInferenceRequest` contract.

- The immutable ordered host `candidate_ids`, snapshot identity, table schema/order digest, and `global_candidate_count=N` describe the full static candidate table. They remain independent of K and never encode dynamic row-map values.
- Add explicit `policy_width=K`, continuation-present/protocol metadata, and expected feature shapes to the typed request. Host booleans may only describe immutable request layout; validity itself remains a device tensor.
- The v2 request declares and binds both views: ordinary feature/mask/map shapes `[1,K,40]`, `[1,K]`, `[1,K]`; continuation query/mask/map shapes `[1,K,40]`, `[1,K]`, `[1,K]`; expected response utility and uncertainty shapes `[1,K]` and `[1,1]`; and hidden-state shape `[1,64]`. Output metadata echoes protocol, request identity, snapshot, static table digest and K. The ordinary and continuation row maps are device `int64` tensors. Active ordinary entries map one-to-one, in approved policy order, to global rows. A valid continuation map has exactly one active entry in slot 0, identifies the appended continuation row, and is disjoint from ordinary rows. Padded slots use a fixed sentinel and are masked. No `.item()`, `.tolist()`, `.cpu()`, NumPy conversion, Python bool on tensor, or implicit device scalar truth may inspect maps or masks.
- Broker validation checks protocol, static metadata, tensor dtype/device/rank/shapes, and static input order without synchronizing dynamic tensor values. Device-side guards validate range, uniqueness, eligibility, sentinel/mask agreement, and continuation identity. Responses bind protocol, request identity, snapshot, and static table digest. Mismatch fails closed to the already approved device fallback.
- C1 scores both views independently. C2 builds the shared recurrent context from ordinary active rows only, scores ordinary queries and the continuation query against that context, then emits separate ordinary and continuation utilities. Preserve the registered 20 raw features plus 20 missingness indicators and checkpoint parameters; the request/input protocol may version, but learned parameter shapes do not change.
- Old full-table requests and their capture artifacts remain legacy-only. Never relabel a v1 full-table request as the new candidate-view protocol. A v1/v2 mismatch is rejected.

## Request capture and deployment compatibility

`frc_defense/meco_request_capture.py` is an opt-in CPU-copy/NPZ export path used by ONNX verification/export consumers. Whole-compute GPU-only rules prohibit silently using it on v2 live tensors. Therefore v2 capture is deliberately **unsupported and fail-closed before tensor iteration or device-to-host copy**:

- Regular v2 inference is supported and unchanged when capture is not requested. Only when the opt-in capture environment is enabled for a v2 C1/C2 request, `capture_request` rejects the candidate-view protocol before iterating the input mapping, inspecting any tensor/map, copying to CPU, or creating an artifact. The existing adapter may report the capture failure as a warning and continue regular inference; capture is diagnostic and cannot change a policy decision. No v2 capture file is produced.
- `load_capture` and `validate_capture_inputs` reject metadata claiming the v2 candidate-view protocol, including any hand-authored/forged file. Existing legacy full-table capture load/export/parity remains supported under its original protocol and validation.
- Operational consequence: production-capture-bound ONNX export and capture-based ONNX parity are unavailable for v2 C1/C2. They must stop with an explicit unsupported-protocol error rather than reuse legacy shapes. A separate approved offline synthetic/export-fixture plan is required before claiming v2 deployment or ONNX parity. Do not add a CPU-capture exception in this tranche.
- Default synthetic export and seeded parity have the same gate: they must not fall through to `dummy_inputs(track)` / `_seeded_inputs(...)` for a v2 C1/C2 model and emit or validate a graph against the legacy single-candidate-input contract. Require an explicit candidate-view protocol at the export/verification API boundary. For C1/C2 v2, reject before checkpoint load, dummy input creation, output-directory creation, `torch.onnx.export`, or ONNX Runtime invocation, whether inputs would otherwise be synthetic or capture-bound. An unspecified C1/C2 protocol also fails closed; legacy synthetic or capture export/parity remains available only when explicitly identified as the legacy full-table contract and validated against legacy input names/shapes. A v2 capture additionally fails in `load_capture` before graph verification.
- Add the guard in the Python export API so direct callers cannot bypass the CLI, and have `scripts/export_meco_onnx.py` require/forward the protocol for C1/C2. Add the matching guard to `verify_onnx_parity` and its CLI so synthetic-seeded and production-capture verification both report a clear unsupported-v2 status for C1/C2; A1/A2/A3 contracts remain unchanged. No v2 ONNX artifact or passing parity claim may be emitted. No campaign capture, dashboard, checkpoint, model artifact, or existing capture is read or rewritten during implementation of this plan.

## Invariants and Pass 3 evidence

Exact-head Pass 3 must reject unless it independently verifies:

1. Both ordinary and continuation feature tensors are exactly `[1,K,40]` (K=8/16/32); no extra/offset/recall rows enter either view. Continuation never consumes an ordinary prefix slot. With valid continuation, response utilities are exactly `[1,K]` and `[1,1]`, then the device selection vector has K+1 options ordered as K ordinary then continuation.
2. Eligibility is applied before the ordinary K cap; invalid extra rows do not displace direct goals/offsets. The stable K ordinary source order and K8 IDs remain as specified by the candidate contract.
3. C1 uses the same encoder/scorer parameters and global/hidden state for both query views. C2 computes one prefix-only recurrent state from the K ordinary rows, reuses it to score the continuation query, and never reruns/replaces the GRU state for continuation. Masked padding has no effect on context or output; zero active ordinary rows produce a finite zero candidate-context contribution, and zero feasible K+1 options take the typed fallback path. This is the protocol's explicit context rule, not a claim of old K+1 mean-pool equivalence.
4. Row maps and masks stay device-resident, with no dynamic D2H or implicit host synchronization. The chosen local K+1 output index maps to the correct global candidate row/action/route/target using device mapping (`j<K` ordinary map, `j==K` continuation map). Tests verify deterministic lowest-index ties, K+1 stochastic mask/log-probability correspondence, and route status/path/cost plus inference provenance in evaluation route trace.
5. Versioned v2 metadata is separately bound from static N-row IDs and old full-table requests. Malformed/mismatched protocol or tensors fail closed. V1 consumer tests still pass.
6. `capture_request` detects v2 before iterating the mapping, touching feature/map tensors or copying to CPU; a trap tensor/sidecar row map proves no dynamic tensor/map serialization and no artifact is written. `load_capture`/`validate_capture_inputs` reject v2 metadata; legacy captures still round-trip. Only opt-in capture and ONNX export/parity are unavailable for v2; regular inference without capture continues. Direct API and CLI tests prove both synthetic/default and capture-bound export/verification reject v2 before checkpoint/input/output/ONNX work and report the unsupported protocol clearly. Legacy/A-track export/parity remains unchanged.
7. Focused tests and exact code diff stay within the allowlist. No runtime, simulator, training, campaign, checkpoint, GPU, dashboard, or replay operation is part of Pass 1 or allowed during implementation while live training owns the devices.

- Whole-compute normative plan `0fc594792e233c471d3e81c871e595b09bb13f039ddc7f6996afbda389cbaab0` §4 requires preserving current Plan C K-prefix and continue-slot semantics, immutable global order and device-side commitment/candidate logic.
- Current `frc_defense/meco_candidates.py` explicitly constructs `selected_policy = ...[:candidate_k]`, then appends `continue_index`; candidate config says ordinary prefix at K=8/16/32 plus at most one continue row. This confirms K+1 selectable options, not K total.
- The Plan C route slice specifies candidate feature tensors `[1,K,40]` and K=8/16/32. `frc_defense/meco_tracks.py::MecoInferenceRequest` currently couples host `candidate_ids`/mask digest to model width; C1/C2 adapter shape checks also use `len(candidate_ids)`.
- `C2MapCrossAttentionGRU.forward` currently uses candidate queries' unmasked mean as recurrent context. The new protocol replaces that ambiguity with ordinary-prefix-only shared context and a separate continuation query, making its semantics testable without a K+1-width feature tensor.
- `meco_request_capture.py::capture_request` copies request tensors via `.detach().to(device="cpu")`; loader/validator and `scripts/export_meco_onnx.py` / `scripts/verify_meco_onnx_parity.py` consume its artifacts. V2 rejection therefore must occur before capture copy, and v2 ONNX capture use remains explicitly unsupported.
- `frc_defense/meco_deployment.py::export_track` at lines 397–438 loads the model at entry, calls `dummy_inputs(track)` when `input_tensors is None`, and then calls `torch.onnx.export`; `scripts/export_meco_onnx.py` line 31 calls it with `None` inputs when no production capture directory is supplied. Therefore capture rejection alone cannot guard synthetic export. `scripts/verify_meco_onnx_parity.py::verify_onnx_parity` creates seeded inputs in its no-capture branch and invokes ONNX Runtime later; it also needs an explicit protocol guard for both branches.
