## Decision: two K-width score views, K+1 device-side selectable options

The approved candidate semantics are **K ordinary policy-ranked candidates followed by one optional dynamically revalidated continuation candidate**. Thus there are K+1 selectable options when continuation is valid. Do not reserve a slot by dropping the Kth ordinary candidate. At the same time, the Plan C model input contract caps each candidate-feature view at exactly `[1,K,40]`, where K is 8, 16, or 32. No model input tensor may include inactive extras, expanded offset rows beyond the ordinary K-prefix, or recall-oracle rows.

Resolve the width/set mismatch using two explicit, aligned device score views in one versioned C1/C2 request:

1. `ordinary_features: float [1,K,40]`, `ordinary_valid_mask: bool [1,K]`, and `ordinary_row_map: int64 [1,K]` represent the stable, eligibility-filtered ordinary policy prefix. This is the only view that establishes the C2 candidate context.
2. `continuation_features: float [1,K,40]`, `continuation_query_mask: bool [1,K]`, and `continuation_row_map: int64 [1,K]` represent only the optional continuation query in slot 0; all remaining slots are inert masked padding with a sentinel row map. If no continuation is valid, the whole view is masked and no continuation utility is accepted.
3. C1/C2 return `ordinary_utility: float [1,K]` and `continuation_utility: float [1,1]`; uncertainty outputs have matching widths. Hidden state has the existing `[1,64]` shape and is produced once. The post-model policy layer concatenates utility/uncertainty on device into K+1 entries; this output/selection vector is not a model input view and never crosses to host.
4. C2 encodes ordinary features and computes the masked ordinary query mean once; its GRU updates hidden state once from the existing global state plus this prefix-only pooled context. The continuation feature is then encoded and cross-attended to the same map tokens, fused with the **already computed ordinary-prefix GRU state**, and scored with the same scorer/uncertainty heads; it must not invoke the GRU again or replace/augment the shared context. Thus no second candidate context is recomputed for the continuation. If there are zero valid ordinary rows, use an all-zero pooled candidate contribution and still apply the existing global/hidden recurrent update; masked reduction must remain finite. C1 has no candidate-pooled recurrent context: use the same C1 candidate encoder/scorer parameters and the same global/hidden state for ordinary and continuation query views, producing the continuation score independently without consuming an ordinary slot. In each view, active rows occupy a canonical prefix; continuation is active only at slot 0. Pad unused feature rows with finite zeros, set their masks false and row maps to fixed sentinel `-1`. If no continuation exists, all continuation mask entries are false and its utility is excluded. If no ordinary row and no continuation are valid, take the established typed no-feasible/fallback path without sampling an invalid index. These are explicit model-context amendments to the prior all-row K+1 C2 mean pool; they preserve the selectable candidate set and are subject to Pass 3 behavioral review. If Pass 3 finds the shared-context/two-query contract cannot be implemented without wider feature tensors or CPU transfer, stop for a new product decision rather than shrink the prefix or widen input.
5. After scoring, selection uses the exact established ordered set: local indices `0..K-1` identify ordinary rows in approved eligibility-filtered rank order; local index `K` identifies continuation. For device-selected local index `j`, select `ordinary_row_map[j]` when `j<K`, otherwise `continuation_row_map[0]`, using device predicates/gather only. Gather global-table action, route, goal, target and provenance by that global row. Mask padded entries and invalid continuation with `-inf` before argmax/categorical selection. Deterministic ties select the lowest valid local index, so ordinary rows precede continuation on equal utility. Stochastic selection samples the same masked K+1 categorical distribution and records that selected local index's exact log probability; no host-side index conversion is allowed. Preserve deterministic fallback, commitment revalidation and switch-cost semantics.

## Required coordinated device command, macro, and evidence boundary

The earlier postdispatch host-row lookup design is rejected and must not be implemented. The whole-compute contract prohibits both selected-action numeric transfer and host interpretation of dynamic selected identity. Plan C's source slice and action-macro plan currently permit a simulator handoff/report projection that does not satisfy that broader contract. This amendment does not silently reinterpret those permissions: it requires the upstream Plan C, common PPO/action-macro, simulator, and record contracts to be amended and reviewed together before implementation. Until then this candidate-view design is not implementation-ready.

### Device-resident command and execution

1. Keep the local selected index, mapped global row, action tensor, target/goal tensors, route result, selected log probability, actor mask, recurrent state, commitment state, and inference provenance on device through PPO bookkeeping and execution. No selected action, row, candidate ID, route identity, or derived numeric value is copied to Python. The current simulator-facing `gather_action_payload` / `_run_macro_step` Python boundary is not an acceptable terminal consumer.
2. Add a device command interface consumed by the simulator's native tensor/HIP path. It accepts device-resident command tensors and performs legality/remasking, macro continuation/termination, action ticks, physics, rewards, and state updates on device. Macro control must not require a Python action integer or host scalar predicate. The device action used by simulation must be the same tensor decision whose exact selected log probability and identity are retained for PPO/replay.
3. Candidate identity cannot be a host-created per-decision string table under the whole-compute rule. Replace it in the live path with a closed `meco-candidate-descriptor-v2` table. Each final global row has fixed little-endian fields: `kind:u16`, `variant:u16`, `source_identity:i64`, `action_index:i16`, `target_identity:i64` (`-1` if absent), `goal_ref:i32`, `route_ref:i32`, and `valid:u8`, with reserved padding bytes required to be zero. `kind`/`variant` must be from an exhaustive static enum dictionary; unknown values fail closed. Dynamic source/track identity and row ordering are tensors generated on device. The device computes SHA-256 over the canonical ordered descriptor bytes plus schema ID and row count; no host-created per-decision string list or host digest is part of v2. The continuation has kind `CONTINUATION`, binds the active commitment identity, and always maps to final policy-table row `policy_stop`, never source-pool `continue_index`.
4. The final selected global row and descriptor remain device tensors. On device, bind descriptor, selected local/global indices, action, selected log probability, inference provenance, route status/cost/path, executed action/macro ticks, and table digest into one `meco-route-evidence-device-v2` record. ABI v2 is fixed little-endian: 8-byte magic `MECORTE2`; `u16 version=2`; `u16 header_bytes=188`; `u32 record_bytes=220+8P+M`; `u32 descriptor_schema_id`; `u32 route_schema_id`; 32-byte device SHA-256 of the ordered descriptor table; then `u32 selected_local`, `u32 selected_global`, the 32-byte selected descriptor, `u8 action`, `u8 route_status`, `u8 route_valid`, `u8 reserved=0`, `u16 route_cost_units`, `u16 reserved=0`, `f32 selected_logprob`, `f64 route_cost`, `f64 path_distance`, `f64 endpoint_error`, `u32 path_count`, `u64 macro_start_tick`, `u64 macro_end_tick`, `u16 executed_action_count`, `u16 reserved=0`, 32-byte immutable inference/checkpoint provenance digest, `P` pairs of `f32` route coordinates, `M` action bytes, and a 32-byte device SHA-256 trailer over all preceding record bytes. `P` is the exact fixed route-buffer capacity in the route protocol and `M` is the immutable `action_ticks` setting bound in the manifest; record length is fixed from those static values, and unused path/action slots are zero. `route_schema_id` pins the exact route-status enum and `normalized_grid_edge_units` cost contract. For `route_valid=false`, route numeric fields use finite zero sentinels and path/action counts remain explicit; a nonzero `route_valid` requires finite metrics and `path_count<=P`. The action byte must be in the simulator's legal action domain. Every integer/float has the stated width and endianness. Unknown descriptor/status/units, invalid row/map, path overflow, incomplete macro, or table/provenance mismatch produce an invalid device status and cannot produce an accepted record. No host code validates or recomputes dynamic fields.
5. A device serializer writes a complete opaque byte payload. Host performs only byte-for-byte I/O to a preallocated, administratively named sidecar; no `.item()`, `.tolist()`, CPU row lookup, ID formatting, JSON reconstruction, hashing, aggregation, or numeric validation occurs on host. The record path/slot is allocated before selection and does not encode selected row or outcome. Missing, truncated, schema-mismatched, or device-invalid payloads fail closed and cannot qualify or seal an evaluation.

### Replay and dashboard compatibility decision

The current consumers are incompatible with opaque v2 evidence: `_validate_meco_replay_alignment` in `meco_track_training.py` requires decoded `candidate_id`, action, and goal fields; `meco_dashboard.py` requires `route_trace` to be a nonempty list of dictionaries; `meco_validation_campaign_runner.py` hashes decoded route JSON; and dashboard replay JavaScript expects decoded frame decisions. They may not silently parse or hash the opaque bytes under the current whole-compute contract.

The requested dashboard replay view therefore needs a separately reviewed, explicitly non-gating display-reader amendment to the whole-compute contract. That reader may consume only the completed v2 evidence artifact, must not feed training, action choice, evaluation metrics, qualification computation, campaign sealing, readiness, or artifact digests, and must display unsupported/missing evidence as unavailable. A human may review the rendered evidence, but software may not turn that display-reader result into a pass/fail or numeric gate. If that amendment is not accepted, the dashboard must not claim v2 route/action identity visibility and the v2 evaluation cannot pass the requested replay-review gate. The record ABI, dashboard/replay schema, and validation campaign consumer must be versioned together; do not preserve v1 field-level assertions by fabricating host-decoded values. A Pass 2 implementation cannot begin until this reader boundary and the device simulator consumer are approved.

The device evidence ABI may emit a device-produced structured payload for the approved reader, but host storage remains opaque byte I/O. Its decoder is display-only and non-gating; it may map the closed `kind`/`variant` enums and render the bound action/route values exactly as recorded, but cannot compute a route digest, aggregate a metric, choose/derive which action executed, determine eligibility, or make a qualification decision. Device-generated validity and digest bytes are carried unchanged for a separate device-side validator; host does not verify/hash them. The legacy v1 JSON route trace remains readable for existing artifacts. V2 must identify itself explicitly and all unupgraded consumers must reject it as unsupported. The selected candidate label is reconstructed only by the approved display reader from the ABI enum plus its numeric identity columns; there is no host `candidate_ids[row]` lookup in training/evaluation.

This makes the distinction explicit: **K is the ordinary policy-prefix/model-view width; continuation is the approved appended slot with its own K-width padded query view; the policy selection width is K+1 when continuation is present.** The route/recall pool may be larger, but only the K ordinary prefix and one continuation query may participate in C1/C2 computation. This is a deliberate Plan C model-context amendment: C2's recurrent state sees the valid ordinary K-prefix only; the continuation is scored against that same state and is not added to the shared context pool. This preserves the K ordinary choices, appended continuation choice, and shared context across candidate utilities, while making the previously implicit K+1 pooled-context behavior explicit and replaceable under the exact K-view cap. It does not assert bitwise equivalence with the old context.

## Static descriptor schema, device identity, and protocol migration

Add a discriminated C1/C2 candidate-view protocol (for example `plan-c-k-prefix-plus-continuation-v2`). Do not infer this protocol from tensor shapes or weaken the legacy `MecoInferenceRequest` contract.

- Legacy v1 retains its immutable ordered host `candidate_ids` and existing request semantics. V2 does not carry a dynamic host `candidate_ids` list. It binds a versioned static descriptor schema/dictionary (candidate-kind and variant enums only), snapshot/config identity and descriptor schema digest; dynamic candidate identity columns and ordered-table digest are device-produced.
- Add explicit `policy_width=K`, continuation-present/protocol metadata, and expected feature shapes to the typed request. Host booleans may only describe immutable request layout; validity itself remains a device tensor.
- The v2 request declares both views: ordinary feature/mask/map shapes `[1,K,40]`, `[1,K]`, `[1,K]`; continuation query/mask/map shapes `[1,K,40]`, `[1,K]`, `[1,K]`; utility/uncertainty shapes `[1,K]` and `[1,1]`; hidden-state shape `[1,64]`. It also carries the static descriptor schema version and request/config identity. Row maps and descriptor columns are device tensors; no selected or dynamic row identity is copied into host response metadata. Broker validation checks protocol, static metadata and tensor dtype/device/rank/shapes without synchronizing dynamic values. Device guards validate range, uniqueness, eligibility, sentinel/mask agreement and continuation identity; responses bind protocol/request/snapshot/schema identity without a host-computed dynamic table digest. Mismatch fails closed to the device fallback.
- C1 scores both views independently. C2 builds the shared recurrent context from ordinary active rows only, scores ordinary queries and the continuation query against that context, then emits separate ordinary and continuation utilities. Preserve the registered 20 raw features plus 20 missingness indicators and checkpoint parameters; the request/input protocol may version, but learned parameter shapes do not change.
- Old full-table requests and their capture artifacts remain legacy-only. Never relabel a v1 full-table request as the new candidate-view protocol. A v1/v2 mismatch is rejected. The device-produced ordered-table digest in v2 is part of the opaque evidence ABI; a host may not recompute it from a dynamic ID list.

## Request capture and deployment compatibility

`frc_defense/meco_request_capture.py` is an opt-in CPU-copy/NPZ export path used by ONNX verification/export consumers. Whole-compute GPU-only rules prohibit silently using it on v2 live tensors. Therefore v2 capture is deliberately **unsupported and fail-closed before tensor iteration or device-to-host copy**:

- The v2 scorer request is defined here, but production execution is not ready until the coordinated device command/PPO/macro/simulator boundary above is integrated. When opt-in capture is enabled for a v2 C1/C2 request, `capture_request` rejects before iterating the input mapping, inspecting any tensor/map, copying to CPU, or creating an artifact. No v2 capture file is produced.
- `load_capture` and `validate_capture_inputs` reject metadata claiming the v2 candidate-view protocol, including any hand-authored/forged file. Existing legacy full-table capture load/export/parity remains supported under its original protocol and validation.
- Operational consequence: production-capture-bound ONNX export and capture-based ONNX parity are unavailable for v2 C1/C2. They must stop with an explicit unsupported-protocol error rather than reuse legacy shapes. A separate approved offline synthetic/export-fixture plan is required before claiming v2 deployment or ONNX parity. Do not add a CPU-capture exception in this tranche.
- Default synthetic export and seeded parity have the same gate: they must not fall through to `dummy_inputs(track)` / `_seeded_inputs(...)` for a v2 C1/C2 model and emit or validate a graph against the legacy single-candidate-input contract. Require an explicit candidate-view protocol at the export/verification API boundary. For C1/C2 v2, reject before checkpoint load, dummy input creation, output-directory creation, `torch.onnx.export`, or ONNX Runtime invocation, whether inputs would otherwise be synthetic or capture-bound. An unspecified C1/C2 protocol also fails closed; legacy synthetic or capture export/parity remains available only when explicitly identified as the legacy full-table contract and validated against legacy input names/shapes. A v2 capture additionally fails in `load_capture` before graph verification.
- Add the guard in the Python export API so direct callers cannot bypass the CLI, and have `scripts/export_meco_onnx.py` require/forward the protocol for C1/C2. Add the matching guard to `verify_onnx_parity` and its CLI so synthetic-seeded and production-capture verification both report a clear unsupported-v2 status for C1/C2; A1/A2/A3 contracts remain unchanged. No v2 ONNX artifact or passing parity claim may be emitted. No campaign capture, dashboard, checkpoint, model artifact, or existing capture is read or rewritten during implementation of this plan.

## Invariants and Pass 3 evidence

Exact-head Pass 3 must reject unless it independently verifies:

1. Both ordinary and continuation feature tensors are exactly `[1,K,40]` (K=8/16/32); no extra/offset/recall rows enter either view. Continuation never consumes an ordinary prefix slot. With valid continuation, response utilities are exactly `[1,K]` and `[1,1]`, then the device selection vector has K+1 options ordered as K ordinary then continuation.
2. Eligibility is applied before the ordinary K cap; invalid extra rows do not displace direct goals/offsets. The stable K ordinary source order and K8 IDs remain as specified by the candidate contract.
3. C1 uses the same encoder/scorer parameters and global/hidden state for both query views. C2 computes one prefix-only recurrent state from the K ordinary rows, reuses it to score the continuation query, and never reruns/replaces the GRU state for continuation. Masked padding has no effect on context or output; zero active ordinary rows produce a finite zero candidate-context contribution, and zero feasible K+1 options take the typed fallback path. This is the protocol's explicit context rule, not a claim of old K+1 mean-pool equivalence.
4. Row maps, masks, selected local/global rows, action, log probability, descriptors, route evidence and provenance stay device-resident through PPO, action macro and simulation. No dynamic D2H or host selected-action/identity interpretation is permitted. The selected K+1 index maps by device logic (`j<K` ordinary map, `j==K` continuation map); after compaction the continuation global row is `policy_stop`, not source `continue_index`. The device simulator consumes that action tensor. Device evidence binds descriptor, action, exact route status/path/cost, macro result and inference provenance into v2; host writes bytes unchanged. The dashboard reader can view v2 only after separate whole-compute authorization and cannot gate any result. Tests verify ties, stochastic mask/log-probability, and device-side action/evidence binding.
5. Versioned v2 metadata is separately bound from static N-row IDs and old full-table requests. Malformed/mismatched protocol or tensors fail closed. V1 consumer tests still pass.
6. `capture_request` detects v2 before iterating the mapping, touching feature/map tensors or copying to CPU; a trap tensor/sidecar row map proves no dynamic tensor/map serialization and no artifact is written. `load_capture`/`validate_capture_inputs` reject v2 metadata; legacy captures still round-trip.
