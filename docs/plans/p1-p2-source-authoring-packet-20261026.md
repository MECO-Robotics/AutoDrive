## Decision

P1 pre-G0 source-only authoring is authorized within its accepted finite allowlist. The accepted predecessor package plan required G0 before source work, but the exact successor plan below replaces that source gate after receiving Pass 1 ACCEPT and has assigned distinct planner, implementer, and reviewer roles. The corrected P1.1 map and P1.2 static event-field registry have exact-head SOURCE/API ACCEPT. These accept static evidence and the fixed field registry only; they do not accept a transition-envelope or producer API. P1.3 producer and P1.4 consumer/artifact work remain blocked on unresolved semantics. The owner contract fixes episode-local event sequence reset only under a new `episode_generation`; deterministic same-tick allocation order remains unresolved, along with physical generation lifecycle, tick/elapsed-time sampling, and the canonical ledger consumer. P2 authoring still waits for a complete accepted P1 API/source candidate. G0 remains required for all execution and integration.

The P1.1 static source map and P1.2 fixed event-field registry are complete and independently accepted at the exact pins below, on source base `6ed961a09c08dfc1796d98ae3566bd3f0eaaaf22`. The successor plan has exact-head Pass 1 ACCEPT and assigned roles: planner `/root/p1_p2_planner`, implementer `/root`, pre-G0 SOURCE/API reviewer `/root/p3_p4_planner`. The P1.2 acceptance covers only the fixed field registry; no transition envelope or event producer API is accepted. Do not make unresolved semantics normative. P1.3 producer and P1.4 consumer/artifact edits remain blocked on physical-generation lifecycle, deterministic same-tick event allocation order, tick/elapsed-time sampling, and canonical ledger-source decisions. Sequence reset is already specified by the accepted owner contract as episode-local, restarting only under a new `episode_generation`; it is not an unresolved reset choice. Stop for a reviewed amendment if accepted source/contracts cannot resolve remaining questions. The packet update itself is documentation-only and changes no source.

G0 does not gate P1/P2 source authoring or static review. It does gate builds, test execution, numerical/runtime work, simulator/profiler, device/GPU access, dashboard work, training, checkpoint mutation, integration, merge, and promotion. The active campaign and device leases remain outside this packet's authority.

## Existing score-event plan assessment

The existing `gpu-resident-score-event-buffer` plan (`codex/gpu-score-event-buffer-plan-20261026`, head `47ff1037dc5bf0035b5a1d4523f5bddae240351e`, file `docs/plans/gpu-resident-score-event-buffer-20261026.md`, SHA-256 `3095cbee304f21d1d84ae91c1152722f955df47fba58f2399d3e6302d518eff1`) is useful prior design evidence but cannot become the P1 package plan through a status/pin amendment alone. It targets the legacy episode recorder cap of 32,768 accepted events and a passive report drain. The reconciled P1 ABI instead requires a distinct fixed 2,304 × 59-byte batch table, full-capacity staging before mutation, and all-or-nothing transition failure. The existing plan also requires editing `frc_defense/meco_track_training.py`, which the accepted overall plan reserves exclusively to P5, and it does not pin an exact source base or exact fixture/test allowlist. A derivative needs substantive source-map, contract, and ownership redesign with a new review; that design is unresolved and outside this packet. No implementation was authorized from that plan.

The P0a approval resolves the protocol choices. The P1 plan/role gates permit bounded source-only work; the corrected P1.1 map and P1.2 static event-field registry are accepted. They do not authorize a transition envelope, producer/consumer runtime API, or P1.3/P1.4 work. Sequence reset semantics are fixed under a new `episode_generation`; same-tick ordering, physical-generation lifecycle, tick/time sampling, and canonical ledger-source decisions remain open. P2's own plan is accepted but its complete P1 API prerequisite is outstanding. Exact seed/case bytes and opponent identities remain source-bound protocol outputs to freeze before new training or outcomes.
