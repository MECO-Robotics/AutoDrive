# Phase 0 baseline, calibration, and held-out protocol completion plan

**Planner base:** `b8a1b308fb1d2d984555b08ccbdb035bdd4c8fd8` (`origin/main` at planning time)
**Scope:** implementation and evidence protocol for freezing a matched campaign after Phase 2 bundle validation. This plan does not authorize stopping or changing the live r4 supervisor, using its checkpoints as qualified inputs, launching calibration, or consuming either WX9100 while r4 holds both devices.

## Goal and current boundary

Establish an immutable, source/runtime-bound baseline and held-out protocol that implements source plan §§5–6. Calibration must estimate D0 variance and compare predeclared matched deterministic references on identical calibration episodes. Only after those artifacts exist may a reviewer set operational match-point and safety margins and freeze a new target protocol. Future qualification must measure paired held-out match outcomes and safety rates under that protocol.

Keep the active r4 run labeled **diagnostic**. It has no qualification protocol binding, covers only `pickup_simple`, and cannot be retroactively assigned a protocol created later. Optimizer update counts, dashboard summaries, or r4 evaluations do not satisfy baseline, calibration, held-out, or promotion criteria. No current model is qualified.

- `qualifications/meco/d0-calibration-pickup_simple.json`, its bundle, and the `pickup-simple-20261024` shards cover only `pickup_simple`. That complete calibration has not been produced.
- `frc_defense/meco_qualification.py` contains matched-reference calibration and v4 protocol construction/validation. It supports D1/current or D2/cv or D2/multi_model_v1, paired to D0 on the calibration seed table, and binds explicit reviewed margins. The older `docs/implementation-provenance/matched-reference-variance-calibration.md` records reviewer status as pending, while the later integrated review summary `docs/implementation-provenance/qualification-v4-matched-reference.md` records approval of the v4 code. Code review is approved; no matched-reference runtime report/bundle, approved margin-review artifact, or generated v4 protocol is present. - Existing calibration rows and calibrated protocol gates center on `useful_throughput` plus robot/field/wall contact rates. Source plan §6 names held-out **match outcomes** as primary, with paired confidence intervals and no increase in safety violations. Qualification has no `match_points` calibration summary, paired match-point gate, or reviewable operational threshold for that primary criterion. ## Ordered work

### Pass 1 — freeze source, baseline, and split contracts (offline implementation)

1. Add an immutable baseline-freeze artifact under `qualifications/meco/` for the next campaign. It must bind the clean source commit/tree and source-plan digest; simulator/runtime and dependency identity; robot dynamics and geometry; field/layout hashes and legal connectivity; opponent/controller identities; action/update cadence; sensor/noise profiles; scoring and safety-event semantics; and all configuration hashes that can affect outcomes. Include a canonical digest and strict schema/version validation. Fail closed on dirty or ambiguous source/runtime identity.
2. Audit the actual simulator constructors, scoring/event recorder, legal graph, and scenario registry to map every required freeze field to its authoritative source. Store field-level values/hashes, not prose attestations alone. If a value is not observable or reproducibly pinned, mark the freeze incomplete and prevent protocol generation.
3. Create a new immutable partition/protocol artifact for the next campaign. Partition train, calibration, validation, and final test by exact seed tables and held-out *whole* defender families, layouts, and starting situations before any new training. Preserve source-plan held-out families and shifted structures; verify no seed, case, policy family, layout, or start-condition leakage across partitions. Keep final test inaccessible to training, calibration, reference selection, margin selection, and iterative model choice.
4. Do not rewrite v1 or historical v2–v4 documents. Add `meco-qualification-v5` for the match-outcome primary gate and bind it to this baseline freeze. Maintain read-only compatibility for historical reports while rejecting their use as evidence for the new campaign.
5. Add validator/mutation coverage for missing freeze fields, source/runtime drift, dirty checkout, altered scoring/safety schema, overlap or duplicate partition assignments, changed partition hashes, and attempts to bind an old diagnostic manifest/checkpoint. Extend the training manifest handoff so new training must name the immutable baseline/protocol IDs before launch.

### Pass 2 — complete D0 and paired reference calibration (evidence tooling, then later runtime)

1. Reuse the D0 campaign's existing 12-scenario shard/receipt/merge contract, but bind every manifest and merged bundle to the new baseline-freeze digest, clean source identity, normalized runtime, protocol identity, and exact calibration seed-table hash. Reuse old `pickup_simple` reports/shards only when all these identities and per-row semantics exactly match; otherwise regenerate under a fresh campaign ID.
2. Extend matched-reference calibration to resumable immutable shards with exact work-unit coverage and retry semantics, following the D0 coordinator. Calibration arms must use identical case/category/stratum/seed/repetition tuples for D0 and exactly one predeclared reference choice from D1/current, D2/cv, or D2/multi_model_v1. Bind predictor/configuration identity and all simulator inputs. Do not select the reference using validation or final-test outcomes.
3. Record and validate per-episode match points using the source plan's scoring definition, plus useful throughput and all three safety rates. Bind each score to simulator record/replay provenance, exact condition/policy, seed, repeat, and score-accounting semantics. Distinguish policy contribution from team score if both exist; select the primary endpoint to match §6 before generating reports. Never infer match points from throughput or dashboard counters.
4. Merge only complete shards with unique coverage, matching source/freeze/runtime/protocol/seeds, stable raw-row digests, and valid score/safety provenance. Emit immutable D0 and matched-reference calibration bundles with per-stratum means, between-seed and within-seed variance, paired differences, and uncertainty summaries. Reject incomplete, mixed, duplicated, or drifted evidence. Exercise resume, malformed receipt, changed-row, overlap, and merge rejection paths offline.
5. Later runtime collection is a separate gated evidence pass. It may start only after the user ends r4 and both WX9100 leases are free; use the frozen campaign manifests and registered device/runtime requirements. This planner does not stop r4, acquire devices, run a simulator, or create calibration evidence.

### Pass 3 — review operational margins and freeze qualification gate

1. Produce a human-authored, immutable margin-review artifact only after complete D0 and selected-reference bundles have been reviewed. It must bind their exact digests, baseline/protocol identities, reviewer and timestamp, primary match-point estimand, target scenario/scope, minimum operationally useful gain and rationale, uncertainty rule, and non-inferiority margins for each safety-rate metric.
2. Do not invent universal numeric thresholds or auto-derive an operational threshold from observed variance. Reviewers choose the operationally meaningful threshold from robot/game requirements; calibration uncertainty may inform the decision and final detectable/gate threshold, but must not substitute for the explicit rationale. Missing review or any unbounded margin leaves the protocol provisional.
3. Make `meco-qualification-v5`'s primary promotion test the paired held-out match-point difference against the chosen matched control with the preregistered confidence interval and minimum useful gain. Separately require every safety-rate paired interval to remain within its preregistered non-inferiority margin versus the frozen floor/control. Keep throughput, navigation, robustness, and latency as secondary/reporting gates where explicitly declared; none can override primary match outcome or safety failure.
4. Bind final validation and final-test seed/policy/layout pools, CI method and resampling settings, episode/repeat counts, reference/control identities, metric schema, margins, and report validators into the protocol digest. Use validation only for preregistered selection; unlock the final-test ledger once for the selected frozen bundle, and reject protocol edits or repeated peeking.
5. Add end-to-end report intake tests showing that an unbound r4 record, v1–v4 legacy protocol/report, throughput-only success, missing match score, changed baseline, incomplete scenario closure, unsafe CI, or leaked test seed cannot produce a qualified/promotion result. Keep legacy evidence readable but diagnostic-only.

## Required artifacts and provenance

The implementation tranche should leave: baseline-freeze schema/compiler/validator; a new held-out split and protocol artifact; resumable matched-reference shard schema and coordinator; match-score/safety calibration report schema and validator; reviewed margin-review schema/validator; new protocol gate and manifest binding; focused offline contract/mutation tests; and a concise implementation/reviewer record. Runtime evidence remains separate: complete D0 campaign bundle, selected-reference paired bundle, approved margin review, and future held-out five-track/control reports with replay provenance. The implementation pass must not fabricate these runtime artifacts.

## Acceptance criteria

- The baseline artifact can be reproduced from a clean pinned checkout and refuses omitted or changed dynamics, geometry/connectivity, opponent, cadence, sensor, scoring, safety, simulator, or dependency identity.
- Partition validation proves train/calibration/validation/test disjointness and held-out family/layout/start-condition boundaries; test data cannot enter training, calibration, reference choice, or margin review.
- The future D0 schedule validates exactly 12 registered scenarios, 466 strata and 139,800 records at the stated 100 × 3 design; all shards are source/freeze/runtime/protocol bound and resumable. No claim of completed D0 calibration until the full merged bundle exists.
- D0 and one selected deterministic reference are pairwise complete on identical calibration tuples; report intake validates match-point scoring plus throughput and all safety metrics, with stable raw-row and bundle digests.
- The `meco-qualification-v5` protocol remains provisional until explicit reviewer margins are bound. Qualification uses paired held-out match-point CIs and safety non-inferiority; throughput-only reports cannot pass it.
- r4 remains explicitly unbound and diagnostic. No artifact produced by this plan may relabel its checkpoints or historical outputs as matched, held-out, calibrated, or qualified.
- No GPU/simulator/training action is accepted as part of planner or offline implementation review. A later runtime/evidence task must wait for both WX9100 leases to be naturally available and report exact source, protocol, campaign, device/runtime, seed, and artifact identities.
- Update `MECO_FULL_PLAN_EXECUTION_STATUS.md` to distinguish implemented code from generated evidence and current campaign state when those later tranches are integrated; correct the stale v4 summary without claiming a generated v4 report or a qualified result.
