# Neural architecture screening under simulated perception

> Completed V5 study: all 119 training cases passed the structural/checkpoint audit; all 15 CNN map diagnostics, six absence references, and four fresh replay reviews are complete. See [findings](NN_ARCHITECTURE_FINDINGS.md) for results, the known baseline test failure, and trajectory reproducibility limits. Earlier comparisons remain withdrawn.

This study asks which observation representation and policy architecture learns useful tactics earliest, from simple FUEL pickup through deterministic defense. It does not assume that CNNs win, or that a short unsuccessful trial rules out a newer architecture. The seven implementations are runnable candidates; performance claims must come from the saved PPO simulator experiments, rather than this literature review or network tests.

The current action head retains eight categorical tactics. Pickup scenarios mask scoring, interception, and ferry actions 4/5/6 to isolate acquisition and prevent collect/release/reacquire loops. Driving, pickup execution, and navigation still rely on the existing controllers and planner. Consequently, results measure architecture choices within those scenario action masks. A policy cannot select an arbitrary map location simply because its encoder recognizes a promising cluster there. A later controlled experiment could score every retained FUEL track or select a validated waypoint/cell goal, using the same candidate set for all encoders. That would test whether wider spatial context helps decisions that the current four-candidate collection head cannot express. It would change the action problem and must be reported separately from this seven-model screen.

## What the seven alternatives test

Names in executable registries are authoritative if they differ from the study labels above. The implementation sources are `frc_defense/architecture_dense.py`, `architecture_cnn.py`, and `architecture_entities.py`.

**Baseline MLP reproduces the existing categorical network architecture.** It uses two 128-unit tanh layers and separate linear actor/value heads. A network test loads the existing `ActorCritic` weights and checks exact output parity. It reproduces that network, not every detail of an earlier training run.

**Residual MLP is a scalar capacity/optimization control.** Three pre-LayerNorm residual blocks operate at width 128, with GELU activations and a 0.5 residual scale. Residual learning has strong evidence for optimizing deeper image networks, but that does not establish a PPO advantage here. This is an adaptation of the residual principle, not a reproduction of ResNet, and changes normalization, activation, depth, and capacity together. A gain over baseline would justify further controlled ablations. [He et al., Deep Residual Learning](https://arxiv.org/abs/1512.03385).

**Full-field CNN tests spatial locality and weight sharing.** Three small strided convolutions encode a 12-channel 32×64 raster. The final 4×8 map is flattened, retaining coarse absolute position; a scalar branch preserves precise robot and candidate measurements. DQN established that convolutional encoders can support learned game control, but its pixel input, replay-based Q learning, and Atari tasks differ from this semantic-raster PPO study. Our CNN adapts the spatial encoder idea, not DQN's algorithm or exact architecture. [Mnih et al., Human-level control](https://www.nature.com/articles/nature14236).

**Full-field ResNet tests a stronger spatial encoder.** Pooling stages and preactivation residual blocks follow an IMPALA-inspired design, followed by the same spatial flattening and scalar fusion. IMPALA provides relevant visual-RL precedent, while its distributed actor/learner and V-trace training are not used here. Additional depth might help obstruction and congestion patterns; it might also demand more data before exceeding the smaller CNN. [Espeholt et al., IMPALA](https://proceedings.mlr.press/v80/espeholt18a.html).

**Deep Sets tests object precision with inexpensive aggregation.** A shared entity MLP feeds masked mean, maximum, and log-count summaries alongside scalar context. Permutation invariance prevents storage-slot order from becoming an artificial signal. This adapts the set-function construction; mean/max/count is our particular pooling choice. Independently encoding entities before pooling can obscure detailed pairwise geometry, even when individual locations are precise. [Zaheer et al., Deep Sets](https://arxiv.org/abs/1703.06114).

**Entity Transformer (`entity_attention`) tests relational reasoning.** Two pre-normalized Transformer encoder blocks relate 64-dimensional entity embeddings and an always-valid scalar context token. Each has four-head self-attention, a 64→128→64 feed-forward network, residual connections, and padding masks. This is a compact entity Transformer, not a patch-based vision Transformer. No entity sequence positions are added. Set Transformer motivates attention over unordered inputs; relational RL supplies direct evidence that relations between entities can aid learned control. This compact context-token policy does not reproduce those papers' full architectures or training. It could learn relationships such as an opponent approaching a lane near the defender; whether it does so must be inspected, not inferred from attention weights alone. Attention computation also grows quadratically with entity count. [Vaswani et al., Attention Is All You Need](https://arxiv.org/abs/1706.03762); [Lee et al., Set Transformer](https://proceedings.mlr.press/v97/lee19d.html); [Zambaldi et al., Relational Deep RL](https://arxiv.org/abs/1806.01830).

**Field FNO is an exploratory global spatial alternative.** Three layers combine learned low-frequency Fourier mixing with pointwise convolution at width 16. Explicit coordinates, boundary padding, a 4×8 spatial readout, and scalar fusion adapt the operator block into a policy. The originating evidence concerns PDE solution operators, not sparse sensor fields or PPO. Global mixing may connect distant geometry in fewer layers, but truncating modes may smooth small FUEL clusters, and FFT periodicity can create boundary artifacts. Padding reduces rather than eliminates that bias. The pointwise branch retains local signal. This remains a useful hypothesis even if a first trial is slow or weak. [Li et al., Fourier Neural Operator](https://arxiv.org/abs/2010.08895).

## Perception, geometry, and information fairness

Every learned policy must act on the normal simulated perception pipeline. Scenario setup may position true objects, and the evaluator may read truth to calculate outcomes; neither permission grants the policy hidden object positions. Full-field describes the raster's coordinate extent, not complete knowledge of the field.

The end-to-end privacy contract also covers navigation and post-step track maintenance. The v4 audit found truth-driven planner obstacles, proactive robot contention, contact-based FUEL-track deletion, and an enemy ETA feature using hidden speed parameters. Corrected code uses anonymous valid opponent tracks, known own/team telemetry, and this robot's calibrated speed as a prior. Neural offense now receives opponent sensor tracks through the same simulated pipeline; the old role gate excluded it. Physical contacts, public match state, task rewards and replay rendering may use simulation truth. Those allowances do not authorize hidden positions or enemy intent as policy/controller inputs. Regressions compare complete prephysics commands and policy inputs under fixed observations while hidden enemies move; direct input-builder tests alone missed the original leaks.


`PerceptionInputs` combines fixed known field geometry with permitted self/team information and retained sensor tracks. Dynamic FUEL channels contain track density, velocity, confidence/freshness, and retained support. Entities retain locations, motion, age, confidence, type, and extent without raster quantization. Unknown and truly empty cells remain ambiguous: the retained-support channel does **not** prove that an unsupported cell was observed empty. A future visibility-history channel should come from sensor coverage, never ground-truth occupancy.

A [saved input figure](../evaluations/architecture-study-20261020/representations/full-field-inputs.png) shows actual 12-channel inputs at seed 100019, tick zero, for scattered pickup and focused defense. The `.npz` arrays and source metadata are retained beside it. This is a representation illustration, not an outcome evaluation. Robot channels clamp coordinates to the raster boundary, so inactive teammates parked outside the field appear in boundary cells in isolated scenarios; those cells do not mean an ally physically occupies the field corner.

Current opponent observations provide one tracked opponent per observing robot. Neither entity attention nor a full-field raster recovers three hidden opponent locations. Richer architectures cannot repair this information bottleneck without a separately justified multi-target perception change.

The raster favors continuous geometry and cluster structure; entities favor sub-cell precision and variable object counts. Both preserve the existing scalars to avoid forcing a coarse map to reconstruct exact pickup/controller measurements. This makes the first comparison practical, but not a pure architecture ablation: the richer models also receive more retained tracks than the scalar candidate summaries.

Robot properties and field geometry stay fixed (`randomize=False`). Isolated pickup uses modest start/ball jitter, while simple pickup preserves the same relative six-ball layout. The held-out seeds therefore emphasize sensor noise and small placement changes; they do not establish robustness to unseen traffic distributions, substantially different clusters, or robot parameters. Those are important follow-up tests of a spatial encoder.

Follow-up controls should separate **information**, **capacity**, and **computation**: compare a flattened full raster MLP at a feasible size, an MLP with expanded entity summaries, approximately parameter-matched scalar models, raster-only versus scalar-fusion models, and masked/dropped channel groups. Keep perception noise, track capacity, normalization, action masks, and rewards identical. Otherwise a spatial model's gain could be extra information, while a loss could be extra optimization burden.

A separate posthoc diagnostic evaluates each final standard-CNN checkpoint normally and with sensed-object raster channels 2/3/4/5/8/11 zeroed, over all five tasks and three training seeds. It retains scalar measurements, entities, public geometry, own/team positions and HUB channels. Complete masked-categorical action traces and their histograms distinguish input dependence from coincidentally equal terminal scores. Fresh normal evaluations are compared with the original final evaluation; frame and metric parity warnings remain visible. This missing-input intervention is out of distribution and keeps scalar redundancy. It measures frozen-policy sensitivity, not the benefit of map inputs during learning; matched retraining and capacity controls remain necessary. These 15 diagnostics are separate from the prespecified 119 training cases.

## Protocol for early learning and deterministic defense

Use actual on-policy PPO rollouts in the simulator. Forward/backward tests establish numerical compatibility; supervised fitting to scripted actions would measure imitation; neither establishes learned simulator behavior. PPO's clipped update procedure is the common training algorithm, with architecture as the experimental variable. [Schulman et al., PPO](https://arxiv.org/abs/1707.06347).

The scenario ladder is `pickup_simple` (six nearby balls), `pickup_scattered` (24 seeded scattered balls), `deterministic_defense` (one defender against a loaded scripted attacker), and `defense_3v3` (three defenders against three deterministic attackers). Start independent runs per scenario to measure acquisition without inherited skill. Transfer/curriculum experiments can follow, with separate reporting because pretrained pickup changes the defense starting condition.

The main pickup, defense, and offense horizons are 4, 8, and 12 seconds. They end before the first HUB activation shift at 30 seconds, so the learning comparison concerns the opening with both HUBs active. It does not measure learned inactive-HUB handling or endgame adaptation. The separate, predeclared 160-second baseline/CNN replays are illustrative full-match transfer checks, not a seven-architecture long-horizon training comparison.

The eight-second full-3v3 task is an opening probe. In several final policies, the recorded representative world has no retained opponent observation and no close encounter within that window. Similar scores there cannot establish equivalent defensive skill or encoder failure. The focused loaded-attacker scenario supplies an earlier encounter for all seven architectures; the separate full-match replays inspect whether interactions eventually occur. Snapshot proximity is sampled and is not a contact detector.

A fifth, explicitly experimental scenario, `offense_vs_deterministic_defense`, tests blue neural offense collecting 24 midfield balls against a deterministic red defender. A research factory supplies the offense configuration without changing the production environment. Its neural action path uses generic strategic execution and lacks deterministic-only intake/scoring refinements. Performance therefore measures architecture learning within this limited execution path; it does not establish parity with the refined deterministic offense controller.

For every architecture/scenario pair, evaluate the initialized model before the first update. Random initialization and categorical sampling can produce useful-looking behavior through the existing tactic controllers. Report improvement relative to this initial control, rather than crediting all final pickup or defensive contact to learning. Include an idle/scripted policy where relevant. For defense, run the same deterministic attackers with **no active defender** under matched seeds: attacker score or progress in isolation establishes what delay or suppression actually means. Contact count alone does not establish effective defense; a defender can collide while accelerating an attacker toward its goal. In this screen, ordinary layers retain their framework defaults and the FNO has explicitly scaled spectral weights. Identical seed identifiers therefore do not match actor-logit variance or initial behavior across model families. The same case seed initializes weights and the training-world generator; held-out evaluation uses seed + 100000. These are paired case identifiers, not a factorial separation of initialization and environment variance.

Record acquisition metrics such as collected FUEL, first-pickup latency, acquisition success fraction, and collection rate over a fixed physical horizon. For defense, report attacker score, score prevented relative to the matched undefended baseline, progress/delay, and meaningful interaction outcomes. Distinguish cumulative training reward from evaluation outcomes so shaping rewards cannot masquerade as task success. Inspect representative records for missed pickups, immobilization, repeat collection/release loops, and useful interception.

The evaluator also records red cumulative score integrated over time (`mean_red_score_integral` and `red_score_integral_per_world`). This delay-sensitive secondary metric can distinguish defenders when all attackers eventually reach the same terminal score: lower integral means less red score accumulated early in the fixed horizon. It is an action-repeat sampled integral, not a continuous collision or scoring-event measurement. First-pickup and first-red-score times are recorded per world, with `None` for events not reached and `timing_resolution_seconds` specifying granularity. Never replace censored events with zero or a fabricated completion time; report success fractions alongside conditional means among reached events. Training logs separately count acquisitions and blue/red scoring events to expose sparse task feedback hidden by shaping rewards or canceling mean rewards.

Measure both learning per simulator transition and learning per wall-clock second. Plot initialized performance and checkpoints at common sample budgets; also retain elapsed training/evaluation time and throughput. Define early learning through a prespecified checkpoint interval, area under the evaluation curve, or time/transitions to a prespecified task threshold. Report a threshold never reached as censored, not as a made-up completion time. Larger models can be more sample-efficient while being slower to acquire skill on this machine. The research harness constructs all input representations for every policy, including scalar-only MLPs. This keeps a common preprocessing path but adds avoidable overhead to those baselines; end-to-end benchmark wall times do not equal an optimized production stack comparison. Separate neural forward timings exclude input construction, perception, planning and physics.

Use the same rollout sizes, PPO epochs, discounting, advantage normalization, optimizer, entropy coefficient, clipping, initialization policy, and evaluation action mode across architectures unless the experimental condition explicitly changes them. Implementation details can dominate reported PPO gains. [Engstrom et al., Implementation Matters](https://arxiv.org/abs/2005.12729).

The study defaults `disable_miopen=true` on HIP and uses ATen convolution consistently across all seven alternatives in the actual learning matrix. This hardware workaround changes the execution backend and must accompany timing comparisons; it is not evidence that residual networks are algorithmically unsuitable. Qualification and integration runs are separate from the main learning matrix at `evaluations/architecture-study-20261020/matrix`.

Both GPU slots use AMD WX 9100 cards. Reports group otherwise identical sample-learning protocols across device slots and retain the original device in every case row. Training times remain descriptive because placement and overlapping jobs can affect throughput. These trials are excluded from the learning comparison. No architecture conclusions should be drawn before the corrected matrix and its simulator records have been reviewed.

This is shared across architectures in those scenarios; it means parking does not establish physical absence. The ordinary 3v3 architecture comparison has all six robots active and does not use parked bodies. Treat the isolated-task results as performance in the implemented scenarios, with this physical limitation.

It disables physics graph capture for substep inspection while retaining native GPU physics and simulated perception. Removing blue observers also changes full-3v3 sensor batching, so matched seeds do not guarantee identical sensor-noise streams to the defended condition. Reference score differences are descriptive context, not a perfectly controlled causal estimate. Recorded frames and events match bitwise. Earlier V4 reference numbers are archived as legacy and cannot substitute for current-source reference results. Both failed-case executions are retained without retry in `references-absent-blue-v5-gpu/defense_3v3/seed-100007-n-4-ticks-400/repeat-mismatch.json`. Repeatability at these seeds does not establish universal bitwise reproducibility.

The main matrix uses **3e-4** across 105 cases. The declared extra sweep adds all seven architectures on focused deterministic defense, seed 7 only, at **1e-4 and 1e-3**: 14 exploratory cases, 119 expected overall. These rates are study choices, not paper-derived optima. The one-seed sweep measures sensitivity; it is not nested validation, an independently validated best rate, or a multi-seed ranking. A future tuning study should select on validation seeds before held-out tests. Keep rates separate and publish skipped/interrupted conditions.

Separate training seeds, model-initialization seeds, and held-out evaluation seeds. Pair evaluation scenarios across models; repeat independently initialized training runs, rather than treating many episodes from one trained policy as independent training evidence. With few runs, publish individual results and uncertainty instead of a confident ranking. Use interval estimates and robust aggregate summaries when enough runs exist; do not pool incompatible raw pickup and defense score units. These recommendations follow the evaluation concerns in [Agarwal et al., Statistical Precipice](https://arxiv.org/abs/2108.13264) and [Patterson et al., Empirical Design](https://arxiv.org/abs/2304.01315).

Retain configuration, source revision/dirty-tree provenance, environment/perception settings, seed lists, parameter counts, checkpoint paths, and simulation records. Replays used for review must be freshly produced after restarting the dashboard services on the current checkout, with current frontend assets and responsive endpoints verified. Old-code replays must be labeled outdated. A report must explicitly identify any missing required simulation or dashboard validation.

## Open candidates after the first screen

**Memory: GRU/LSTM, then selective state spaces.** None of the initial seven policies is recurrent. Track age and velocity encode some history, but cannot represent a learned belief about an occluded opponent's intent. Recurrent model-free RL can be competitive on POMDP benchmarks when implemented carefully; that supports a memory comparison, not an assurance of success here. Add sequence rollout storage, hidden-state resets, burn-in and truncated-backprop controls before comparing a GRU variant. [Ni et al., Recurrent Model-Free RL](https://proceedings.mlr.press/v162/ni22a.html).

Mamba's selective state mechanism is a plausible later memory candidate. Its original evidence comes from sequence modeling, not this policy-control setting. Compare against a tuned GRU at realistic observation cadence and sequence lengths, including kernel/runtime availability and inference latency. Do not transfer large-language-model throughput claims to small robot batches. [Gu and Dao, Mamba](https://arxiv.org/abs/2312.00752).

**Graph and equivariant policies.** Explicit edges based on distance, relative velocity, or lane connectivity may give an efficient bias for interception and coordination. Test sensitivity to graph construction and missed tracks. Equivariance should respect actual game symmetries: unrestricted rotations/translations are inappropriate for a fixed field with goals, boundaries, and time-dependent scoring. Relative geometry plus typed goal nodes, or a carefully validated team-side reflection, is more defensible. [Battaglia et al., Graph Networks](https://arxiv.org/abs/1806.01261); [Satorras et al., E(n)-equivariant GNNs](https://arxiv.org/abs/2102.09844).

**Compact spectral set encoders.** A fixed-width Deep Sets implementation does not inherit a universal approximation guarantee for arbitrary large sets; latent capacity matters. [Wagstaff et al., Universal Approximation of Functions on Sets](https://www.jmlr.org/papers/v23/21-0730.html). A 2026 construction uses multiscale random Fourier features to obtain logarithmic dependence on set cardinality for Wasserstein-stable targets, but its dimension bound has strong error-tolerance and element-dimension dependence. That suggests another encoder hypothesis, not evidence that a small random-feature policy will outperform attention here. Contact and scoring thresholds also make the required stability assumption a substantive question for this simulator. This alternative remains untested in the seven-model matrix. [Zhou et al., Compact permutation-invariant approximation](https://proceedings.mlr.press/v306/zhou26ac.html).

**KAN and other new function approximators.** KAN's learnable univariate edge functions offer a distinct alternative for scalar or fusion branches. The original results on fitting functions and PDE problems do not establish noisy on-policy optimization performance. Keep it eligible, but measure spline-grid/input-range sensitivity, update cost, regularization, and PPO stability under changing state distributions. A compact KAN head over a fixed encoder would isolate that question better than simultaneously replacing perception and policy. [Liu et al., KAN](https://arxiv.org/abs/2404.19756).

These follow-ups should be selected from observed failure modes. Poor sensing, inadequate memory, a restrictive action interface, and a weak spatial encoder require different experiments. A short first screen can prioritize investigations; it cannot establish an architecture's ultimate ceiling.
